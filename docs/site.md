# 鹊桥官网与接单（产品）

> 产品拍板：2026-11-05 Asia/Shanghai。部署与技术栈见 `docs/architecture.md` 第 14 节与 `docs/site-deploy.md`，实现交给「鹊桥-服务端」。  
> 同一台低配 ECS（`121.196.45.81`，约 2C2G，已跑中继）。**必须轻便**，不装重组件。

## 要做什么

1. **产品介绍站**（静态页）：鹊桥是什么、怎么用、安全边界、下载入口。
2. **接单页 + 极简后台**：访客提交协助需求；运营者查看/改状态，并有一份按联系方式聚合的客户名单。

这与远程协助控制面里的「中继账号 / 设备免密」不是同一套用户体系，也不升级成完整云端用户中心、计费或组织工单。

## 轻量约束（硬）

- 不安装 Node / Java / PHP / MySQL / Redis / WordPress / Docker 全家桶等重运行时。
- 不和新的数据库服务抢内存；数据用 **SQLite 文件**（可与中继库分文件，避免耦合）。
- 页面用静态 HTML + 少量 CSS/JS，**不**上大型前端框架构建链。
- 独立小进程（推荐与中继同为 **Go 单二进制**），和中继 **分端口**，不要占用 `17891` JSONL。
- 内存与 CPU 增量保持很小，中继优先级高于官网。

## 公开页面

### 首页 `/`

- 品牌：鹊桥远程协助 · 智能体
- 一句话：用命令 + 智能体协助修电脑，不是远程桌面
- 三步：对方安装 → 把会话码和验证密码发给你（或账号免密）→ 连上后排障，危险操作在对方电脑上确认
- 安全：写操作本机确认；中继不代执行
- 下载：Windows 与 Linux 安装包入口链到实际包（R019）；macOS 标明「即将提供」，不假装已可下（未上真机、未验收）。默认小包需附 .NET 8 运行时短说明；没有自包含包就不要写已经提供。

### 接单 `/ask`（或同等路径）

访客填写并提交：

| 字段 | 要求 |
|------|------|
| 称呼 | 必填 |
| 联系方式 | 微信 / 手机 / 邮箱至少一项必填 |
| 系统 | Windows / macOS / Linux / 不清楚 |
| 问题描述 | 必填，短文本即可 |

提交成功给出明确回执（「已收到，我们会通过你留下的联系方式回复」），失败给出可懂原因。不做在线支付、不做实时聊天客服。

## 后台 `/admin`

- 共用一个运营口令（环境变量配置，不进 git）。不做多角色权限系统。
- 订单列表：时间、称呼、联系方式、系统、摘要、状态（新留言 / 已联系 / 已结束）。
- 可改状态、加备注。
- **客户名单**：按联系方式聚合，能看到该客户的历史订单；不是注册登录用户中心，不和中继 `signup` 打通。

## 明确不做

- 完整 CRM / 计费 / 评价 / 工单工作流
- 把官网账号和中继设备账号打通
- 为了官网再装一套重型 Web 栈
- 与中继共用 17891 端口

## 网络

当前生产安全组约定「仅放行 TCP 17891」。上官网后需**额外放行 TCP 80**（若后续上 HTTPS 再放 443）。具体监听、是否绑定域名、证书由架构定；MVP 可用 IP + 80，不阻塞。

## 验收

1. 浏览器打开首页能看懂产品并找到接单入口。
2. 提交一单后，后台能看到；改状态/备注立即生效。
3. 同一联系方式再次下单，客户名单里能归到一起。
4. 服务器无需新装大型软件；官网挂掉不得拖死中继进程。
