## 本轮目标

1. **高频（S005）**：已连上后非自己断开的 `ConnectionLost`，主状态与重连引导改为人话；不得再写成「对方已结束这次协助。」。
2. **打磨（断开之后）**：协助端自己断开用人话「你已断开…」；被协助端断开后说清旧码仍可再用（与产品拍板一致）；断在工具调用中不得停在英文 `Connection closed`。
3. **平台**：Windows（WinForms 去协助 / 接受协助相关句）与 Avalonia 两端，凡有同句则一起改；文案进 `HelperSessionCopy`（或并列常量），两端共用。

## 锁定文案（产品拍板，勿改措辞）

| 场景 | 主状态 / 引导 |
|------|----------------|
| 已连上后中途掉线（非自己点断开） | 主状态：**「连接已断开。」** |
| 同上，同屏引导（失败提示区 / 次要行） | **「若对方仍在接受协助，可再点「连接」；若对方已结束，请对方重新打开接受协助并复制码发给你。」** |
| 协助端自己点断开 | **「你已断开。若要再连，粘贴码后点「连接」。」** |
| 对方明确结束（现有 R035，本轮不扩协议区分） | 仍可保留常量「对方已结束这次协助。」；**中途 `ConnectionLost` 不得再用此句**（无新协议字段，本轮不区分「对方点了结束」与「传输断了」的信令，统一走「连接已断开。」+ 重连引导） |

### 产品拍板 · 旧码

**未刷新会话码则旧码仍可再连。** 断开 / 「结束这次协助」只断开会话，**不作废**当前码与密码；只有「刷新会话码」才换新并作废旧码。引导文案须与此一致，不得暗示未刷新时旧码已失效。

### 与 R035 的关系

- **保留**：自己断开 ≠ 对方结束；尚未连上失败不用结束句；结束后收起五键。
- **修订**：取消「网络中途断开也可以用对方结束句、不必区分」的文案策略；网络中断 / `ConnectionLost` 用上表「连接已断开。」+ 重连引导。

## 验收标准（交给客户端）

1. 已连上后模拟/制造底层断开（非自己点断开）：主状态为「连接已断开。」，同屏可见重连引导句；五键按未连接规则收起；「连接」恢复可点。
2. **不得**在该情景主状态显示「对方已结束这次协助。」。
3. 协助方自己点断开：主状态为「你已断开。若要再连，粘贴码后点「连接」。」；**不要**只写「状态：未连接」；**不要**出本条中途掉线重连引导句。
4. 尚未连上失败：仍为「连接失败」+ R003 原因句，无本条「连接已断开。」。
5. 断在「提议一项改动」或只读工具进行中：稳定后界面符合 1，主状态**不得**长时间停留英文 `Connection closed`（或同类协议原文）。
6. 对方仍在接受协助且未刷新码时，用原码再点「连接」可再次连上（或按 R003 给出明确失败原因）；对方已结束协助后再连，落到 R003 已有引导。
7. 被协助端：对方离开或本机「结束这次协助」后，主状态说清「对方已离开 / 你已结束」且**明确旧码还可再用**；不得以「已断开 N 个会话」当主说明；不得在未刷新时暗示旧码已作废。
8. Windows 与 Avalonia 行为与文案一致；截图放到 `docs/screenshots/r043-*`（勿覆盖 r022–r042）。
