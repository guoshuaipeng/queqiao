## 1. 官网接单页

### 用户 / 场景

访客在介绍页看完产品后，想让运营联系自己（自己电脑有问题，或想请人远程协助）。他们不会注册，也不应被要求「记住单号、回来查进度」。

运营用口令进入后台，按联系方式回人、改状态、看同一人的多次留言。不是派单、不是 SLA、不是组织工单。

### 访客要填什么

表单标题：「需要帮忙？留下联系方式」
表单说明：「不用注册。我们会通过你留下的方式回你。」
主按钮：「发给我们」

| 字段 | 必填 | 上屏标签 | 占位 / 选项 | 用途 |
|------|------|----------|-------------|------|
| 称呼 | 是 | 怎么称呼你 | 例如：小王 | 运营开口用的称呼 |
| 联系方式 | 是 | 联系方式 | 微信、电话或邮箱，方便我们回你 | 回访方式；后台「客户名单」按此归拢 |
| 系统 | 是 | 这台电脑是 | Windows / macOS / Linux / 不确定 | 决定后续发哪边的安装说明，不当工单分类用 |
| 问题描述 | 是 | 需要什么帮助 | 简单说说遇到什么问题 | 运营开口前要知道的事 |

实现说明：联系方式可以拆成微信 / 手机 / 邮箱三项，至少填一项，与「至少一种联系方式」等价，更便于校验；上屏语气仍用上表。

不要加：附件、紧急程度、账号注册、查单号、期望回复时限、指派给谁。

校验失败时：「请填完后再发送。」
联系方式过短时：「请留下能联系到你的微信、电话或邮箱。」

### 提交后访客看到什么

标题：已收到，我们会联系你
正文：会通过你刚留下的联系方式回你，请留意。不用注册，也不用记住单号。
次要操作：返回介绍

不要展示：工单号、进度查询入口、「等待处理中」这类流程话术。
后台内部可以有记录编号，只给运营看，不给访客当查单凭证。

同一联系方式再次提交：访客仍看到同一条成功说明；后台归到同一客户下的新一条留言，不新建一个互不相干的人。

### 后台状态对运营意味着什么

只保留三个状态，默认提交为「新留言」：

| 状态 | 对运营的含义 | 下一步 |
|------|----------------|--------|
| 新留言 | 还没回过，优先看 | 用对方留下的方式联系，联系上再改为「已联系」 |
| 已联系 | 已经接上话，不必当成新单反复抢 | 事情了结后改为「已结束」；同一人又交来新留言，仍应看到 |
| 已结束 | 这件不用再跟 | 从待办里拿掉；客户名单仍保留，方便以后认出是同一人 |

客户名单：按「联系方式」归拢，展示称呼、系统、最近一条留言时间和当前状态。
不要做：指派、优先级、SLA、公开查单、评价、和中继账号绑定。

### 验收

访客填完四项能提交，成功页只有「已收到 + 我们会联系你」，没有查单入口。
运营用口令能看到新留言、把状态改为「已联系 / 已结束」，同一联系方式的多次提交显示为同一客户。
全程不出现工单号查询、登录注册、或与中继账号相关的提示。

## 2. Mac / Linux 被协助 · 亲友三步闭环

节奏（已拍板，不挡 Windows 演示）：先出 Mac/Linux 被协助端和 MCP，再补对等的双模式界面。写操作同样必须本机确认。分发：macOS 为 `.app` + `.dmg`；Linux 先 `.tar.gz`（随后可选 `.deb`）。默认发依赖 .NET 8 运行时的小包，并附简短运行时安装说明；自包含包保留给不愿或不能先装运行时的人。

### 用户 / 场景

家人或朋友用的是 Mac 或 Linux，自己不会排障。协助方在另一台电脑（现阶段可以是 Windows「去协助」或 MCP）连过来查看进程、日志、文件；要改东西时，必须在亲友眼前的这台电脑上点允许。

### 三步（与 Windows 同一条主路径）

1. **安装**：从官网下载对应系统的包并打开被协助端。无需注册。若使用默认小包，按页面上的简短说明装好 .NET 8 运行时；若使用自包含包，则不必先装运行时。
2. **出示凭证**：界面展示会话码和验证密码，亲友点「复制码+密码」，发给要帮自己的人（两行纯文本，与 Windows 相同）。
3. **本机确认**：对方连上后可以查看；真正要改动时弹出确认，点「允许」才执行，点「拒绝」则未做任何改动。

### 和 Windows 相同的部分

- 默认走公网中继，用会话码 + 验证密码配对。
- 写操作必须在被控本机确认，不能由中继或协助方绕过。
- 不做完整远程桌面或键鼠注入。
- 亲友界面不出现 Assist、MCP、ownerLink、TLS、端口号。
- 刷新会话后，旧码旧密失效。

### 和 Windows 不同的部分

| 环节 | Windows | macOS | Linux |
|------|---------|-------|-------|
| 安装 | 安装包，显示名「鹊桥远程协助」 | 打开 `.dmg`，把「鹊桥」拖进应用程序 | 解开 `.tar.gz` 后运行（可随后再提供 `.deb`） |
| 首次系统授权 | 可能弹出「是否允许访问网络」，提示点「允许」 | 可能提示无法验证开发者，需在系统设置里仍允许打开；另可能询问网络权限 | 可能需要先赋予执行权限；不要套用 Windows 防火墙话术 |
| 第一阶段界面 | 已有接受协助 / 去协助双模式 | 先保证被协助端能出示凭证、弹出确认 | 同 macOS：先被协助，再补对等「去协助」界面 |

首次授权话术按系统分别写，不要出现 `17890` / `17891`，也不要把「本机放行入站端口」写进亲友主路径。

### 验收（一句话）

Mac 或 Linux 亲友能独立完成「按说明装上被协助端（默认小包需先有 .NET 8 运行时，或改用自包含包）→ 把会话码和验证密码发给对方并被连上 → 写操作必须在本机点允许后才执行，点拒绝则未做任何改动」；规则与 Windows 相同，仅安装方式和首次系统授权提示不同。
