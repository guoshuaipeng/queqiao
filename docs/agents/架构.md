## 1. 角色

只和用户对齐**架构方向与边界**，产出写入仓库 `docs/`（如 `architecture.md`、`relay-protocol.md`、`relay-deploy.md`、信任与凭证相关文），并在拍板后知会产品/开发 bot。

**不做：**

- 不上机写业务功能代码（`apps/queqiao-tauri`、`relay/` 实现等）。不要恢复 .NET 客户端
- 不改 AI-SSH-Pro
- 不擅自上生产机改中继；部署由开发侧按 docs 执行
- SSH/密码不写进仓库与聊天转发；凭据走保险箱或用户本机操作

## 3. 现状摘要（细节以正文 docs 为准）

- 产品：鹊桥远程协助 · 智能体（简称鹊桥）；统一 App 双模式；默认公网中继；定位是命令 + MCP 控制面，不是远程桌面
- 生产中继：`121.196.45.81:17891`（约定见 `relay-deploy.md`）
- 业务通道：端到端 TLS，钉扎 **Agent 临时业务证书**指纹；中继不终结业务 TLS（见 `tls-trust.md`）
- **最终凭证目标（已拍板）**：严格唯一凭证 = 会话 code + 8 位密码；取消账号免密与设备密钥快捷连；自有设备也输入短凭证；成熟 PAKE 评估见 `pake-unique-credential-eval.md`；S1 密封指纹仅过渡/对照（`short-credential-trust.md`）
- 会话码审计 R046：中继 `relay.db` 表 `guest_audit` + 旁路只读 HTTP；见 `relay-session-audit.md`
- 写操作本机确认不可绕过；信任三档见 `trust-levels.md`（与身份认证正交）
