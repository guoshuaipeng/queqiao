# 鹊桥远程协助 · 智能体 — 产品决策

## 品牌名

- **中文全称**：鹊桥远程协助 · 智能体
- **简称**：鹊桥
- **英文（暂定）**：Queqiao Remote Assist
- 意象：像鹊桥一样把两边连上，用智能体/命令协助修电脑（非远程桌面画面）。

> 独立软件 + 可 MCP 嵌入其他智能体。不做进 AI-SSH-Pro。  
> 约定与决策写进本仓库 `docs/`，**不要只放在 bot 记忆里**。

## 定位

对标向日葵 / TeamViewer 的「远程协助」场景，但**控制面不是远程桌面画面**，而是 **命令 + MCP 智能体**：对方装轻量被控端，协助方（人或 AI/MCP）连上后查进程/日志/文件；**危险操作必须在被协助本机确认**后才执行。不做完整远程桌面 / 键鼠注入。

## 目标用户

亲友 + 客户支持 + 同事运维兼顾。

## 连接（2026-11-05 起）

1. **默认：公网中继**（Go `relay/`，建议阿里云 2C2G；正式默认 `121.196.45.81:17891`，见 `docs/relay-deploy.md`；客户端仍可改）。
2. **访客协助**：被控端展示会话码与验证码（短形态可展示/口述）；主按钮 **「复制连接凭证」** 复制**完整安全载荷**（既有 `remoteassist:pair`，含 code + password + **Agent 业务证书指纹 `fp=`**）。协助端**一个**输入框粘贴该整段后点「连接」。短码或无指纹旧两行可识别但**必须阻断**并人话请对方重发完整凭证。**Windows 主路径（net48）不得以填局域网 IP/端口/TLS 指纹为主操作。** 规范见 `docs/quality-connection-credential.md`（并入 R043）。
3. **账号免密**：简单注册/登录 → 电脑加入账号（设备上线）→ 同账号机器列表 → 连接在线设备（无需再输会话密码）。
4. **局域网直连**保留为高级/调试（历史端口 `17890`，载荷 `via=lan`），非默认。
5. 中继控制面：**JSONL**（见 `docs/relay-protocol.md`）；配对后透明转发。业务层默认 TLS + 证书指纹钉扎（端到端，中继只转发）。`--insecure` 仅显式调试。
6. **业务 TLS 与分享**（见 `docs/tls-trust.md`）：E2E TLS + Agent 临时证书指纹钉扎；默认分享须带完整安全载荷（含 `fp=`）。`{会话码}-{8位验证码}` 只授权中继会话，不能单独建安全业务通道；禁止 TOFU；缺指纹安全阻断，禁止自动降明文/skipTls。

## 鉴权与安全底线

- **访客**：中继 `guest_host` / `guest_join`（code + 密码；**新生成/刷新验证码固定 8 位数字**，字符串保留前导零）。人话主路径复制/粘贴为**完整安全载荷**（含业务指纹）；短码仅展示/口述；无指纹输入须阻断（见 `docs/quality-connection-credential.md`）；刷新会话码须同时换密码。
- **账号**：中继 `signup` / `login` → `token`（约 7 天）→ `device_online` / `list_devices` / `connect_device`。MVP 本地/中继侧轻量存储即可，**不做**完整用户中心 / 计费 / 组织工单。
- **账号免密连自己的机器**：可跳过「配对确认窗」（`ownerLink` 自动批准 Assist 会话）；**写操作本机确认不可绕过**（除非对方主动授予 Admin）。中继配对成功 ≠ 授权写操作。
- 审计写本地日志；敏感路径可读拒绝。

## 权限三级

1. **Guest（访客只读）**
2. **Assist（默认）**：写操作本机确认
3. **Admin**：可跳过部分确认（仍审计）；仅对方主动授予；账号免密默认 Assist

## 产品形态与安装

- **同一安装包、双模式**：接受协助 / 去协助别人；可返回首页。视觉质感以首页和配对确认为标杆，协助端向它们看齐；原则见 docs/quality.md（Windows 主路径为 net48 WinForms，不换框架；net8 自包含安装包为兼容备用）。
- **可选 MCP**：安装或设置里启用 stdio，供协助方 Agent 使用；与 UI 控制端共用同一连接与确认流程。MCP **默认不在「仅接受协助」场景自动对外监听**，避免误暴露。协助端 / 设置里须能看到怎么安装 MCP（复制配置并贴进 Cursor 等工具的 MCP 设置），不用另翻仓库文档。
- 被控：主界面展示 code、验证密码、二维码/载荷、TLS 指纹、配对与审计；可登录绑定账号以上线设备。
- 控制：code+密码或载荷经中继连接；设置里填中继地址；可注册/登录、刷设备列表、免密连接。
- 安装包：`installer/RemoteAssist.iss` → `RemoteAssist-Setup-*.exe`（默认 `%LOCALAPPDATA%\Programs\RemoteAssist`）。
- 兼容：独立 Agent / Helper.UI / Helper CLI / MCP。

## 协助闭环（管理端 / Agent）

1. 协助方把**安装包下载地址**或本机安装包目录发给远端用户。
2. 远端安装后，把 **完整连接凭证**（「复制连接凭证」得到的整段安全载荷；或账号免密场景下的设备已在线）回传协助方。
3. 协助方（人或 Agent via MCP）连上会话，排障；写操作走本机确认。

Skill 仅作「如何安装 MCP / 如何填参数」的薄封装；**控制面与协议以 MCP + 客户端为准**，不做成纯 Skill 远程控制。

## MCP

- 优先通用 stdio；工具与 Helper 同一客户端协议；`run_command` 走确认流程。
- 连接参数支持中继载荷（含 `via=relay&pwd=`）及后续账号 token / 设备连接。

## 确认与审计

配对与 Assist 写操作默认本机确认窗（账号自有设备可跳过配对确认，见上）；串行排队；审计写本地日志。写操作必须在被控本机确认，中继配对成功 ≠ 授权写操作。亲友可见界面不出现 Assist、MCP、ownerLink、TLS。

被协助的人可以在本机设置信任等级（对方不能远程打开），详见 docs/trust-levels.md：

- 每次询问（默认）：所有写操作都弹确认。
- 宽松：高风险仍要确认；其余自动允许并记审计。高风险包括删除文件或文件夹、格式化、关机/重启、改用户或权限、改注册表；「执行命令」若明显命中这类意图也仍要问。这不是完美安全网，所以默认必须是「每次询问」。
- 完全信任：本会话写操作不再弹窗，仍记审计。打开前本机再确认一次；可随时改回；会话结束或换人后不沿用到下一个访客。

访客只读仍是天花板：完全信任也不能让访客写。协助权限决定对方能提议什么，信任等级决定本机还问不问。界面不出现 Assist、Admin、ownerLink。

- 配对确认窗：「有人想协助这台电脑。对方可以查看进程、日志和文件，不能直接改你的电脑。真正要改动时，还会再问你。」按钮「允许协助 / 拒绝」；超时自动拒绝。ownerLink 只跳过此窗，写操作窗仍在。随 R003 验收。
- 写操作确认窗：「对方想在这台电脑执行操作」+ 该次操作的白话说明 +「允许 / 拒绝」。超时不自动允许；拒绝后提示「已拒绝，未做任何改动」。跟 P0「写操作本机确认」一起验收，不另开一轮。

## 官网与接单（2026-11-05）

- 在现有低配中继机上提供 **静态产品介绍** + **接单表单** + **极简后台**（订单状态与按联系方式聚合的客户名单）。详见 docs/site.md。
- 必须轻便：静态页 + 小进程 + SQLite；不装 Node/Java/PHP/MySQL/WordPress/Docker 全家桶；不占用中继 17891。
- 与中继账号/设备体系分开；不因此做成完整云端用户中心、计费或组织工单。
- 安全组需额外放行 HTTP（80；若上 HTTPS 再加 443），由架构写入部署约定。

## 技术选型

- 客户端：**Windows 主路径 = .NET Framework 4.8（`src-net48/` + `scripts/build-net48.ps1`）**，WinForms；演示与验收优先开 net48 产物。**.NET 8 自包含安装包仅作兼容/出包备用**，不是 Windows 亲友主路径。macOS / Linux 仍用 .NET 8 + Avalonia（见 architecture.md 第 13 节）；src-net48 不上 Mac/Linux。
- 公网中继：**Go** + SQLite（`relay/`）
- 二维码：QRCoder
- 帧：业务侧 4 字节 LE 长度 + UTF-8 JSON；中继透明 pipe；控制面 JSONL

## 体积说明

- 小体积是跨平台一等约束。实测基线（2026-11-05，本机 artifacts/）：Windows **主路径** `src-net48` 依赖系统 **.NET Framework 4.8** 约 **1.4 MB**；.NET 8 自包含安装包约 **72 MB**（**兼容备用**，非 Windows 主路径）。演示与验收优先开 net48 产物（`scripts/build-net48.ps1`）。
- **macOS / Linux 默认发依赖运行时的小包**，目标尽量接近上述 1.4 MB 这一档（应力争个位数 MB，而不是默认 72 MB）；对方需已装 .NET 8 桌面方向运行时，首次使用提供简短安装说明。
- **.NET 8 自包含包保留为兼容备用**（不愿或不能先装 Framework 4.8 / 过渡官网大包），体积上限不差于当前约 72 MB；手段为 PublishTrimmed + 单文件，Native AOT 作后续试验。官网若仍挂 net8 大包，视为过渡/备用，产品叙事以 net48 小包为准。
- src-net48 / .NET Framework 4.8 仅适用于 Windows，不能作为 Mac/Linux 的缩体积方案。
