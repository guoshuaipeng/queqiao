# 鹊桥远程协助 · 智能体 — 产品决策

## 品牌名

- **中文全称**：鹊桥远程协助 · 智能体
- **简称**：鹊桥
- **英文（暂定）**：Queqiao Remote Assist
- 意象：像鹊桥一样把两边连上，用智能体/命令协助修电脑（非远程桌面画面）。

> 独立软件 + 可 MCP 嵌入其他智能体。不做进 AI-SSH-Pro。  
> 约定与决策写进本仓库 `docs/`，**不要只放在 bot 记忆里**。

## Bot 职责记忆（换 bot 接续）

各角色站立决策与协作约定见 **`docs/agents/`**（[索引 README](agents/README.md)）：产品 / 客户端 / 服务端 / 架构 / 体验 / 场景。**桌面客户端只有 Tauri**（`apps/queqiao-tauri`）。.NET 客户端已删除，不要恢复。细则以 `docs/agents/产品.md` 与下文为准。

## 定位

对标向日葵 / TeamViewer 的「远程协助」场景，但**控制面不是远程桌面画面**，而是 **命令 + MCP 智能体**：对方装轻量被控端，协助方（人或 AI/MCP）连上后查进程/日志/文件；**危险操作必须在被协助本机确认**后才执行。不做完整远程桌面 / 键鼠注入。

## 目标用户

亲友 + 客户支持 + 同事运维兼顾。

## 连接（2026-11-05 起）

1. **默认：公网中继**（Go `relay/`，建议阿里云 2C2G；正式默认 `121.196.45.81:17891`，见 `docs/relay-deploy.md`；客户端仍可改）。
2. **访客协助（当前安全主路径）**：被控端展示会话码与验证码（短形态可展示/口述）；主按钮 **「复制连接凭证」** 复制**完整安全载荷**（既有 `remoteassist:pair`，含 code + password + **Agent 业务证书指纹 `fp=`**）。协助端**一个**输入框粘贴该整段后点「连接」。短码或无指纹旧两行可识别但**必须阻断**并人话请对方重发完整凭证。**客户端不得以填局域网 IP/端口/TLS 指纹为主操作。** 规范见 `docs/quality-connection-credential.md`（并入 R043）。**体验目标**是主路径只复制短码、地址进高级设置——见下节「体验目标」；在「安全实现前置条件」满足前**不得**把短码当已可安全连接。
3. **账号免密 / 设备密钥快捷连（产品意图已废止 · 2026-11-06 10:35 Asia/Shanghai）**：曾支持简单注册/登录 → 设备上线 → 同账号机器列表 → `connect_device` / `ownerLink` 免输会话密码。用户已拍板 **严格唯一凭证**，本旁路**取消**（自有设备也须输入 code+密码）；现网代码若仍存在，属待收口遗留，**不得**继续宣传为产品能力。见「产品拍板：严格唯一凭证」。
4. **局域网直连**保留为高级/调试（历史端口 `17890`，载荷 `via=lan`），非默认。
5. 中继控制面：**JSONL**（见 `docs/relay-protocol.md`）；配对后透明转发。业务层默认 TLS + 证书指纹钉扎（端到端，中继只转发）。`--insecure` 仅显式调试。
6. **业务 TLS 与分享**（见 `docs/tls-trust.md`）：E2E TLS + Agent 临时证书指纹钉扎；默认分享须带完整安全载荷（含 `fp=`）。`{会话码}-{8位验证码}` 只授权中继会话，不能单独建安全业务通道；禁止 TOFU；缺指纹安全阻断，禁止自动降明文/skipTls。

## 体验目标（用户重申 · 2026-11-06）

> **产品意图**，与「安全实现前置条件」分节。短码本身**不等于**已可安全连接；在架构短凭证方案落地前，连接仍走完整安全载荷（见上节与 `quality-connection-credential.md`）。

1. **复制内容 = 会话码 + 密码（短码）**：主路径目标为 `{会话码}-{8位验证码}`（8 位验证码要求仍有效）。中继地址默认内置，只在**高级设置**修改；亲友**不**复制地址或长串载荷。协助端一次粘贴短码连接——**前提**见下节。
2. **单主窗口**：首页与点击「去协助 / 接受协助」后共用**一个**主窗口，页内切换，不多开主窗口；返回首页不叠窗，保持位置/大小。有活动会话时返回首页或切换角色**不得**暗中断开、留下隐藏会话或自动扩大权限；确需结束须本机确认。**安全确认对话框不在单窗口合并范围**——不得为单窗口取消写操作本机确认。

排期：**R049**（单主窗口 + 高级中继 UI，UX，不改短凭证安全）；**R050**（短凭证可连）**blocked** 等架构。见 `docs/roadmap.md`、`docs/round-049.md`。

## 安全实现前置条件（短凭证）

- **当前**安全连接仍要求完整 `remoteassist:pair`（含 Agent 业务 TLS 指纹 `fp=` / `PairQrPayload`）。R043 信任模型见 `docs/tls-trust.md`，**不得削弱**。
- 短码今日只授权中继会话，**不能单独**建安全业务通道。
- **禁止**：TOFU；跳过校验；把中继回传、未经可信绑定的指纹当独立认证；未验证前把主路径改成「只复制短码却暗连」。
- 短凭证 E2E 方案与迁移/兼容边界由架构另出；未落地前 **R050** 不得开实现。

## 产品拍板：严格唯一凭证（2026-11-06 10:35 Asia/Shanghai）

> **LOCKED PRODUCT DECISION** — 用户经鹊桥-体验明确选择：**严格只认 code+密码，自己的设备也输入，不另设设备密钥快捷连接。**  
> 此前「开放评估 / 等 A/B」**已关闭**。本拍板是产品意图与排期依据；**不是**现网已实现、也**不是**安全 PASS。在架构正式方案落地并通过恶意中继等运行验证前，**不得**宣称已安全满足。

### 拍板内容

- **唯一连接凭证** = 会话 **code + 8 位密码**（sole connection credential）。
- **取消旁路**：账号 / 同 owner 服务器声明免密；设备密钥快捷连接；凡仅凭服务器 `token` / owner 声明即可授权控制的路径（含 `connect_device` / `ownerLink` 免密产品意图）。
- **自有设备也输入** code+密码；不另设设备密钥快捷连。
- **写确认档位正交不变**：Guest / Assist / Admin 与信任等级（每次询问 / 宽松 / 完全信任）的本机写确认规则保持正交；不得把「服务器不可冒充」落实成强制每次写弹窗，也不重置既定三档。
- **服务端不知明文密码**（目标）：中继不得持有可用明文 password；实现路径由架构评估成熟 **PAKE**（禁止自造密码学），见 `docs/pake-unique-credential-eval.md`。
- **安装 ≠ 可被随时控制**：安装/启动/上线本身不授予远程控制；须持有 code+密码并经端点验证 + 本机授权。

### 与现网 / 排期

- 今日安全主路径仍为完整 `remoteassist:pair`（含 `fp=`）；**R043** 信任模型在运行验证完成前**不得削弱**。
- **R049**（单主窗口 + 高级中继地址）：UX，与 PAKE **独立**，规格 draft，**未授权实现**（可另授权）。
- **R050**（严格唯一凭证 / 短码可连）：决策已锁定；状态仍 **blocked** — 等架构正式评估收口 → 产品对照验收标准 → **再授权实现**。未授权前不得改主路径实现。
- 账号注册/登录若保留，仅可用于发现、计费等**非授权**用途；**不得**再作为控制授权旁路。

## 产品拍板：恢复账号设备免密（2026-11-09）

用户明确要求下一版包含账号、设备列表、免密连接、运维和无人值守。本节覆盖上文「取消账号免密 / connect_device」的产品意图。亲友临时协助仍用连接凭证，不强制登录。

- **注册**：客户端内用户名 + 密码，成功后立刻登录。用户名 3–32 位字母、数字或下划线，不区分大小写。密码至少 8 位。不收手机号和邮箱，不提供找回密码。
- **免密范围**：只有这台电脑在本机打开「允许我的账号连接」之后，同一账号才能从设备列表连上。账号令牌不能连上一台从未允许过的电脑。
- **写操作**：默认仍在本机确认。无人值守里的「改动不再询问」默认关闭，要单独确认。
- **短码**（R050）仍不在这一版。

## 鉴权与安全底线

- **访客**：中继 `guest_host` / `guest_join`（code + 密码；**新生成/刷新验证码固定 8 位数字**，字符串保留前导零）。人话主路径复制/粘贴为**完整安全载荷**（含业务指纹）；短码仅展示/口述；无指纹输入须阻断（见 `docs/quality-connection-credential.md`）；刷新会话码须同时换密码。
- **账号**：中继 `signup` / `login` → `token`（约 7 天）→ `device_online` / `list_devices` / `connect_device`。MVP 本地/中继侧轻量存储即可，**不做**完整用户中心 / 计费 / 组织工单。
- **账号免密连自己的机器（产品意图已废止）**：不得再作为出货能力宣传或新增；遗留 `ownerLink` / `connect_device` 免密须在 **R050** 实现收口时移除或隔离。**写操作本机确认不可绕过**（除非对方主动授予 Admin）。中继配对成功 ≠ 授权写操作。
- 审计写本地日志；敏感路径可读拒绝。

## 权限三级

1. **Guest（访客只读）**
2. **Assist（默认）**：写操作本机确认
3. **Admin**：可跳过部分确认（仍审计）；仅对方主动授予；会话默认 Assist（不再有账号免密默认路径）

## 产品形态与安装

- **一个窗口、两件事**：打开就能「请人帮我」和「我帮别人」。界面以 `docs/CLIENT-UI.md` 为准。
- **客户端**：只有 Tauri（`apps/queqiao-tauri`）。.NET / WinForms / Avalonia 客户端已删除。
- **可选 MCP**：设置里可以复制 MCP 配置，供协助方 Agent 使用；与界面共用同一连接和确认流程。MCP 不在「只接受协助」时自动对外监听。
- 被控：主界面展示会话码、密码和连接凭证。连接控制须持有凭证，不再免密连。
- 控制：粘贴完整连接凭证后点连接。中继地址默认内置，只在设置里改。

## 支持平台

- 当前桌面客户端是 **Windows 上的 Tauri**。Mac / Linux 的旧 .NET / Avalonia 客户端已删除，没有替代包之前不要再写成可下载。
- 写操作本机确认在所有平台上都是同一条安全底线。
- 仍有效的服务端工作：**R046** 中继会话码审计（`docs/round-046.md`、`docs/relay-audit.md`）；**R050** 短码可连仍 **blocked**。

## 协助闭环（管理端 / Agent）

1. 协助方把**安装包下载地址**或本机安装包目录发给远端用户。
2. 远端安装后，把 **完整连接凭证**（当前：「复制连接凭证」得到的整段安全载荷；目标主路径：会话码+8位密码）回传协助方。**不再**以账号免密「设备已在线」替代凭证。
3. 协助方（人或 Agent via MCP）连上会话，排障；写操作走本机确认。

Skill 仅作「如何安装 MCP / 如何填参数」的薄封装；**控制面与协议以 MCP + 客户端为准**，不做成纯 Skill 远程控制。

## MCP

- 优先通用 stdio；工具与 Helper 同一客户端协议；`run_command` 走确认流程。
- 连接参数支持中继载荷（含 `via=relay&pwd=`）及后续账号 token / 设备连接。

## 确认与审计

配对与 Assist 写操作默认本机确认窗（**严格唯一凭证**下不得再以账号自有设备跳过身份/配对）；串行排队；审计写本地日志。写操作必须在被控本机确认，中继配对成功 ≠ 授权写操作。亲友可见界面不出现 Assist、MCP、ownerLink、TLS。

**中继会话码审计（R046）**：中继 SQLite 另表记录会话码生成、join 成功/失败、会话结束，供鉴权后的管理台只读列表（created_at / code / status）；**不**存不展验证码、password_hash、fp、完整连接凭证；**不**改 guest_* 协议字段；与官网接单 /admin 分离。见 docs/relay-audit.md。

**短码复制与单主窗口（体验目标）**：复制内容目标为会话码+8位密码；单主窗口页内切换。安全短凭证未落地前主路径仍复制完整连接凭证。见「体验目标」「安全实现前置条件」。R050 blocked。设置里须能复制安装说明和 MCP 配置；缺完整凭证必须阻断，禁止降成明文。

被协助的人可以在本机设置信任等级（对方不能远程打开），详见 docs/trust-levels.md：

- 每次询问（默认）：所有写操作都弹确认。
- 宽松：高风险仍要确认；其余自动允许并记审计。高风险包括删除文件或文件夹、格式化、关机/重启、改用户或权限、改注册表；「执行命令」若明显命中这类意图也仍要问。这不是完美安全网，所以默认必须是「每次询问」。
- 完全信任：本会话写操作不再弹窗，仍记审计。打开前本机再确认一次；可随时改回；会话结束或换人后不沿用到下一个访客。

访客只读仍是天花板：完全信任也不能让访客写。协助权限决定对方能提议什么，信任等级决定本机还问不问。界面不出现 Assist、Admin、ownerLink。

- 配对确认窗：「有人想协助这台电脑。对方可以查看进程、日志和文件，不能直接改你的电脑。真正要改动时，还会再问你。」按钮「允许协助 / 拒绝」；超时自动拒绝。ownerLink 只跳过此窗，写操作窗仍在。随 R003 验收。
- 写操作确认窗：「对方想在这台电脑执行操作」+ 该次操作的白话说明 +「允许 / 拒绝」。超时不自动允许；拒绝后提示「已拒绝，未做任何改动」。跟 P0「写操作本机确认」一起验收，不另开一轮。

## 官网与接单（2026-11-05）

- 在现有低配中继机上提供 **静态产品介绍** + **接单表单** + **极简后台**（订单状态与按联系方式聚合的客户名单）。详见 docs/site.md。
- 必须轻便：静态页 + 小进程 + SQLite；不装 Node/Java/PHP/MySQL/WordPress/Docker 全家桶；不占用中继 17891。
- 与中继账号/设备体系分开；不因此做成完整云端用户中心、计费或组织工单。
- 安全组需额外放行 HTTP（80；若上 HTTPS 再加 443），由架构写入部署约定。

## 明确不做（当前）

- 完整云端用户中心 / 计费 / 组织工单（官网接单后台除外：仅订单+客户名单，见 docs/site.md）
- 修改 AI-SSH-Pro 本体
- 正式 CA 互认（仍用自签 + 指纹）
- 用纯 Skill 替代 MCP/协议作为控制面
