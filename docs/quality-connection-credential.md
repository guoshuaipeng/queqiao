# 连接凭证（会话码 + 验证码）· 产品规范

> 产品拍板：2026-11-06 Asia/Shanghai（用户经由鹊桥-体验提出；产品收口并入 R043）  
> 适用范围：Windows **src-net48**（主路径）、net8 WinForms / Avalonia、CLI 复制与解析。  
> **不要只改显示**：生成、校验长度/字符集、复制格式、粘贴解析必须一致。

## 目标

亲友/客户只复制、粘贴 **一次** 凭证即可连接，避免「先复制会话码、再复制验证密码」两次操作。两项鉴权含义不变（仍是 code + password 配对），只统一展示与输入形态。

## 规则（已拍板）

1. **被协助端（接受协助）主展示与复制**  
   - 主展示与剪贴板统一为：`{会话码}-{8位验证码}`（中间 **ASCII 连字符 `-`**，不是全角横杠）。  
   - 主按钮文案：**「复制连接凭证」**（取代「复制码+密码」作主路径文案；旧文档出现旧按钮名时按本规范理解）。  
   - 复制成功后人话可写：「已复制连接凭证。」（勿把完整凭证写进日志）。

2. **协助端（去协助）输入**  
   - **一个**主输入框接收完整凭证；一次粘贴后点「连接」。  
   - 程序内部拆分为会话码与验证码，两项鉴权含义不变。  
   - 仍接受 `remoteassist:pair…` 载荷（既有能力保留）。

3. **旧格式兼容（必须）**  
   - 仍接受历史两行 / 分栏粘贴：  
     ```
     会话码：AB12CD
     验证密码：3471
     ```  
   - 以及既有「会话码 / 验证密码」分字段或整段两行粘贴，避免已发出去的旧分享失效。  
   - 兼容期：未刷新的旧会话（较短或字母数字验证码）在协助端仍应可解析并用于 `guest_join`。

4. **新生成 / 刷新的验证码**  
   - 固定 **8 位**；**纯数字**（`0–9`）；以 **字符串** 保存，**保留前导零**（例如 `00481273` 不得变成 `481273`）。  
   - 便于口述；刷新会话码时必须同时换新验证码（既有安全底线不变）。

5. **错误文案**  
   - 凭证拆不出完整两项时：  
     **「连接凭证不完整，请复制完整的「会话码-8位验证码」」**  
   - **禁止**把完整连接凭证写入日志、审计对外展示或异常 MessageBox 原文。

6. **三端同步**  
   - Windows WinForms（尤其 **src-net48** 主路径）、Avalonia、CLI 的**复制格式与解析**保持一致。  
   - 优先改共享层（如 `FriendConnectGuide.FormatShareClipboard` / `TryParseShareText`、`SessionPasswordGenerator`、`ConnectDraftParser`），再改各 UI 按钮文案与单框布局，避免只改某一端显示。

7. **鉴权与协议**  
   - 中继仍为 `guest_host` / `guest_join` 的 code + password；**本规范不新增中继协议字段**。  
   - 展示用连字符只存在于「人话复制/粘贴」层；发给中继的 password **不含**中间的 `-`（先拆分再 Normalize / 上报）。

## 与业务 TLS 指纹的分工

- 短凭证 **只**承载会话授权（code + password），**不含**证书指纹。
- 默认公网中继：协助端用客户端**内置官方指纹**做业务 TLS 钉扎。
- 自定义中继：必须改走完整安全载荷（含 `fp=`）或显式配置指纹；不得因短凭证缺指纹而降明文。
- 缺指纹时安全阻断。权威约定：`docs/tls-trust.md`。

## 现状核对（供实现，2026-11-06 只读）

| 项 | 现状 | 目标 |
|----|------|------|
| 默认生成长度 | `SessionPasswordGenerator.Generate` 默认 **4** | 新码 **8** |
| 字符集 | 字母数字表 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`（避开易混字符） | 新码 **纯数字 0–9**，保留前导零 |
| 客户端下限 | `RelayClient`：`password.Length < 4` 抛错；PRODUCT「密码最少 4 位」 | 继续接受 ≥4 的旧码；**新生成固定 8 位数字** |
| 复制格式 | `FormatShareClipboard` → 两行「会话码：/验证密码：」 | 主路径改为 `{码}-{8位}`；两行解析保留兼容 |
| Normalize | `Trim` + 大写 + 去空格 + **去掉 `-`** | 拆分凭证时须 **先按首个/约定规则拆出 password，再 Normalize**，避免把「码-密码」整段当 password 去横杠后粘成一串 |

## 待客户端 / 服务端核实（开放问题）

实现前请在本轮回报（写入 round 交付说明即可）：

1. **今日线上/本机实际生成长度与字符集**是否仍为默认 4 + 上述字母数字表（含 net48 是否另有一份生成逻辑）。  
2. **中继**是否只做字符串相等，有无最大长度、字符集、或「必须 4 位」的校验；8 位数字 password 能否直接 `guest_host` / `guest_join`。  
3. **迁移**：已发出、尚未刷新的短码/字母数字码，协助端兼容解析是否覆盖；刷新后旧凭证失效（既有语义）是否在 UI 有一句人话。  
4. 会话码本身若含易与分隔符混淆的字符时，拆分规则（建议：自右取 8 位数字为验证码，左侧为会话码；或仅在「恰好一段且含一个 `-`」时拆分，并与两行解析短路顺序写清）。
