# 鹊桥 · 质感续篇：断开之后说清下一步

> 对照 `r031-avalonia-peer-disconnected.png`（被协助端）与 R039 协助端断开截图。  
> 只改「断开之后」亲友 / 客户主路径上的状态与下一步文案，不碰 macOS 正式下载、HTTPS、中继协议。  
> 体验主笔；产品 2026-11-06 收口写入。R042（官网包跟上 R041）进行中；本项排为 **R043 候选**，不在此开实现。

## 结论

被协助端有人断开后，不要只写「已断开 1 个会话」。用人话说清是谁断了、旧码还能不能用、下一步点哪。协助端自己断开时，也不要只剩「状态：未连接」。

## 产品拍板（旧码是否仍可再连）

**未刷新则旧码仍可再连。** 断开 / 「结束这次协助」只断开会话连接，**不作废**当前会话码与验证密码；只有「刷新会话码」才换新并作废旧码（既有确认窗不变）。

理由：亲友误断、协助方掉线后，应能用同一份码重新连上，少一步「先刷新再重发」；需要换人或防旧码外泄时，再主动刷新。

## 断点

亲友这边刚被断开：顶上写「已断开 1 个会话。」，凭证区仍是原来的会话码和验证密码，下面又写「已连上网络，可以发给对方了」。亲友分不清：对方还能用旧码重连，还是要再复制发一次，还是要先刷新。客户支持收尾时同样会卡在这一步。

协助端自己点断开后，状态回到「状态：未连接」，和从未连过一样，看不出「是你刚断开的」。对方结束时已有「对方已结束这次协助。」，自己断开应对齐成同样清楚的一句话。

## 改法

### 被协助端（亲友 / 客户）

对方断开或本机「结束这次协助」之后：

1. 状态区改成一句人话（按真实原因）：  
   - 对方断开：`对方已离开。旧码还可再用，把下面的码再发给对方即可；若要换新码，再点「刷新会话码」。`  
   - 本机结束：`你已结束这次协助。旧码还可再用；若还要请人帮，把下面的码再发给对方即可（或先点「刷新会话码」换新的）。`
2. 保留当前码；主按钮仍是「复制码+密码」。**不要**自动刷新，**不要**在未刷新时暗示旧码已作废。
3. 「已连接的协助方」在无人时保持「(暂无)」；不要用「已断开 N 个会话」这种计数当主说明。
4. 若网络仍通，可保留次要句「已连上网络，可以发给对方了」；须与「旧码还可再用」不打架。

### 协助端

1. 自己断开后，状态写：`你已断开。若要再连，粘贴码后点「连接」。`  
   不要只写「状态：未连接」。
2. 对方结束时，保留现有「对方已结束这次协助。」；常用操作区继续隐藏（与 R039 一致）。  
   （R035 `StatusDisconnectedSelf` 原文「状态：未连接」仅保留给「尚未连上 / 连接失败清理」等非「自己刚断开」场景；自己断开改用上一句新人话，需共用常量并锁测。）

## 验收

- 被协助端：对方离开后的截图上，主状态不是「已断开 N 个会话」；能读出对方已离开，且明确「旧码还可再用 / 再发给对方」；不得写成旧码已作废却仍展示同一码。
- 被协助端：本机点「结束这次协助」并确认后，状态写明已结束，并提示旧码仍可再发（或可选刷新）。
- 协助端：自己断开后状态为人话「你已断开…」，不是单独的「状态：未连接」；对方结束仍为「对方已结束这次协助。」
- 本项不改官网下载、macOS 分发、HTTPS、中继或配对协议；不改刷新确认窗原文。

## 不做

- 不重做 R039 五键首屏，不改 R041 连上后人话状态的既有结论。
- 不改写操作确认、信任等级文案。
- 不开本条实现轮（等 R042 验收后由产品开 R043）。

## 产品收口

- **R043 候选**：被协助端断开后人话 + 协助端自己断开人话；规则锁定「未刷新旧码仍可再连」。
- 优先级：R042 官网包验收通过后再开实现。
