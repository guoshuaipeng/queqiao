# 停止接受，以及复制何时算成功

等待中点「停止接受」：先作废这一代，界面进入「正在停止接受协助…」，再在后台丢掉套接字。读循环最多再等一轮超时就退出，然后回到空闲，清掉会话码和凭证。后台线程在世代已经变了之后不再刷新界面。每张界面快照带递增序号，旧序号到了也不再画。

复制：写入之后读回，和内存里的凭证一致才提示「已复制，请完整发给对方。」否则提示「没能复制，请再点一次。」并让原文框获焦。失败不报成功。

## 验收结果

本机中继 `127.0.0.1:17991`。点「开启接受协助」后出现「等待对方连接」「复制连接凭证」「停止接受」，密码是圆点。点「停止接受」后回到「开启接受协助」。没有「复制连接凭证」，没有「等待对方连接」，没有「正在接受协助 · 已连接」，原文框里也不再有凭证。另一扇窗口用刚拿到的凭证点「连接」，没有「有人想协助这台电脑」，也没有已连接；协助端是「没能连上，请检查网络后重试。」图：`acceptance/desktop-before-stop.png`、`desktop-while-waiting.png`、`desktop-after-stop.png`。

同一构建上点「复制连接凭证」：出现「没能复制，请再点一次。」，原文框获焦，没有「已复制，请完整发给对方。」这张图含凭证，未保存。

剪贴板仍写不进去。`OpenClipboard` 返回错误 5，当前打开者窗口是 0。任务对象没有剪贴板限制（界面限制位是 0）。脱离任务的进程 `childInJob=0`，窗口站 `WinSta0`、桌面 `Default`，自建窗口后再打开，仍是错误 5。`clip.exe` 退出码 1。`Clipboard.SetText` 抛出「所请求的剪贴板操作失败。」本机剪贴板用户服务实例在跑，当前进程没有权限重启它。所以不能说复制已经成功。绕过：系统允许打开剪贴板时，失败框已获焦，再点一次或自行复制即可；本机要先由有权限的人重启该用户的剪贴板服务或重新登录，这一步这里没做成，也不知道做了之后会不会好。

`npm run check` 7 项通过。`cargo test` 17 项通过。发布构建已完成。不是两台电脑，也不是生产中继。
