# 旧结果到底后再横滑，仍停在最底下

之前的结果已经停在最底下时，横向滚轮滑到行尾，竖向仍停在最底下。

滑完后位置和可滑尽头一致，`exit=0` 仍留在左边。

## 做法

横向滑动时记下竖向位置。松手对齐如果赶在这次横滑期间发生，先把竖向拨回最底下，不按行高另对齐。

## 验收结果

本机中继 `127.0.0.1:17991`。之前的结果自己能往下滚 96，先停在 96。协助页被临时撑开，放在纵向 40、横向 40。

改之前：横向滚完，竖向仍是 96，横向 730，和可滑尽头一致。`QUEEND` 在 672–712，`exit=0` 在框里。整页仍是纵向 40、横向 40，文档横向仍是 0。

改之后再测，数字相同。

图：`acceptance/desktop-pbottom-old-before.png`、`desktop-pbottom-old.png`、`desktop-pbottom-before.png`、`desktop-pbottom-after.png`。带 old 的是改之前。前一张整页被临时撑开。图里没有完整连接凭证。

横滑到行尾后再往上翻，这一轮没有另测。

`npm run check` 49 项通过。`cargo test` 23 项通过。发布构建后做了上述点击。不是两台电脑，也不是生产中继。剪贴板错误 5 仍在，本轮没有把它当成已修好。
