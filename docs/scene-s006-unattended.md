# S006 — 无人值守：长久 code+密码闭环

> 场景：鹊桥-场景 · 2026-11-06 Asia/Shanghai  
> 状态：场景闭环已写入；**两处产品默认已拍板**（见下）；交互稿由 **鹊桥-体验** 出并与用户确认后锁文案；**未开实现轮**。  
> 约束：**严格唯一凭证**（仅 code+8 位密码 / 当前完整连接凭证）；**禁止**账号免密、`ownerLink`、`connect_device`、设备密钥旁路。不碰完整远程桌面 / 键鼠注入；不把短码未落地前写成已可安全连接（见 `docs/quality-connection-credential.md`、R050 blocked）。

## 结论

三条用户里，**同事运维（及少数客户支持机房/店内机）需要「人不在旁边也能连上」**。今日只有「接受协助」临时会话码：刷新即废、配对要人点允许、完全信任不能跨会话——无人时连不上或连上也不能写。  
本条要补：**本机显式开启的长久协助码**，与临时协助码并列；连接仍只认 code+密码（或当前完整安全载荷）；结束/撤销路径清晰。

**已定行为**：

1. 长久码与临时码**两套凭证**，界面分开展示，互不顶替。  
2. 开启无人值守 = 本机二次确认；持该长久码连接时**跳过配对确认窗**（授权绑在码上，不是绑账号）。  
3. 开启时可**勾选**「无人时写操作不再询问」（语义对齐完全信任：仍审计；仅对该长久码有效）；不勾选则只适合只读排障。  
4. **撤销长久码**立即作废旧码并断开已用该码的连接；不得用账号侧「踢设备」代替。

## 产品拍板：两处默认（2026-11-06 Asia/Shanghai）

> **LOCKED** — 鹊桥-产品按场景文档推荐收口；交互逐字仍等体验稿经用户确认。

### ① 临时结束 ≠ 自动撤销长久码

- 结束临时协助 / 点「结束这次协助」**不**自动撤销长久码。  
- 若确认窗提供「一并撤销长久码」，须为**显式另选项**，且**默认不勾选**。  
- 撤销长久码的主路径仍是本机「撤销无人值守 / 撤销长久码」或「刷新长久码」。

### ② 「无人时写操作不再询问」默认不勾选

- 开启无人值守时，该选项**默认不勾选**。  
- 须机主在本机**显式勾选**，并走**二次确认**；勾选后写操作可不弹窗，**必须可审计**。  
- 未勾选时写操作仍走本机确认（无人则协助方一直等待，属预期）。

## 用户 / 场景

| 角色 | 谁 | 在哪 |
|------|----|------|
| 机主 | 同事运维本人，或客户支持现场负责人 | **有人时**在被控本机开启 / 撤销 |
| 协助方 | 机主自己从另一台电脑，或受委托的同事 | **无人时**用长久码连上排障 |
| 非目标 | 亲友临时帮父母修电脑 | 继续走**临时协助码**，不引导开无人值守 |

- **场景**：机房/办公室电脑常开接受协助；人离开后仍需用同一套 code+密码连上查看或改动；任务结束后能作废凭证，避免码泄露后长期可连。
- **现状断点**：
  1. 临时码刷新/结束协助后协助方无法再连；无人时没人点「允许协助」。  
  2. 完全信任「不能跨会话、不能开机默认」——无法覆盖「明天再连同一台无人机器」。  
  3. 账号免密已废止——无人值守**不得**回退到 `ownerLink` / 设备列表免密。

## 与临时协助码的区分

| | 临时协助码（现网主路径） | 长久协助码（本条） |
|--|--------------------------|-------------------|
| 谁开启 | 打开「接受协助」即有 | 本机显式「开启无人值守」 |
| 寿命 | 刷新会话码或结束协助即废（或等同现网 guest 生命周期） | 直到本机**撤销**或**刷新长久码**（临时「结束这次协助」默认不动长久码） |
| 配对确认 | 要本机点「允许协助」（现网） | 开启时已授权：**持该长久码连上可跳过配对窗** |
| 信任 / 写 | 本机三档；完全信任仅当前会话协助者 | 「无人时写操作不再询问」**默认不勾**；显式勾选 + 二次确认后才免问（仍审计） |
| 复制形态 | 当前：完整连接凭证；目标：短码（R050） | **同一套凭证规则**，不另发明编码，不另开账号旁路 |
| 典型用户 | 亲友 / 客户当面协助 | 同事运维无人值守 |

验收：界面文案能让机主分清「这次请人帮」和「无人时也能连」；不得把长久码画成登录账号。

## 步骤（可开发需求）

### A. 有人时：开启

1. 被控本机（接受协助）提供入口（文案/位置由体验出稿）：开启无人值守。  
2. **本机二次确认**（必须）：说明持码者可在无人时连上。  
3. 「无人时写操作不再询问」：**默认不勾选**；若机主勾选，须在二次确认中写明仍记审计、可随时撤销，未确认不得生效。  
4. 生成**长久** code + 8 位密码；按当时安全主路径提供复制（完整连接凭证，或 R050 落地后的短码）。  
5. 机主把凭证存到自己可控处（密码管理器等）——产品不云端代存明文密码。

### B. 无人时：连接

1. 协助方粘贴**同一形态**凭证，点「连接」（严格唯一凭证；禁止免密列表连入）。  
2. 中继 + 业务 TLS 规则与现网一致（`tls-trust.md`）；缺指纹等仍阻断。  
3. 配对确认窗：**不弹出**（因开启时已授权该码）。  
4. 权限：默认 Assist；访客只读天花板不变。写操作：  
   - 未勾选「无人时写操作不再询问」→ 仍弹本机确认（无人则协助方一直等，属预期）。  
   - 已勾选（经二次确认）→ 本会话写操作不弹窗，**必须记审计**；界面不出现 Admin/ownerLink 字样。

### C. 结束后：撤销

1. 本机「撤销无人值守 / 撤销长久码」（体验出稿）：确认后 **旧码立即失效**，已建立连接应断开。  
2. 「刷新长久码」= 新码生效、旧码失效（与临时码刷新同安全语义）。  
3. 对**临时**访客点「结束这次协助」：**不**自动撤销长久码。若确认窗提供「一并撤销长久码」，须显式另选项且**默认不勾选**。  
4. 撤销长久码不应妨碍另行发起的临时协助（若产品允许并存）。  
5. 撤销后主状态人话提示「长久码已作废，无人时不能再连」（逐字由体验锁）。

### D. 泄露与审计

- 码泄露 = 持码者可连：唯一补救是本机撤销/刷新。  
- 审计：谁何时用长久码 join、写操作记录仍在本机；中继侧若有会话码审计（R046）可记 code 级事件，**禁止**存/展密码与完整凭证。

## 验收（收口句）

1. **开启**：本机未二次确认前不生成可用长久码；确认后可复制凭证。  
2. **连接**：仅持正确长久 code+密码（或当时完整安全载荷）可连；无账号免密入口可达同一效果。  
3. **配对**：用该长久码连上时本机不弹「允许协助」；用临时码连上时行为仍按现网临时路径。  
4. **写权限**：「无人时写操作不再询问」默认不勾；未勾选时写操作仍等本机确认；显式勾选并二次确认后写操作不弹窗但审计可查。  
5. **撤销**：撤销或刷新后，旧码再连失败且有人话原因；已连接被断开。  
6. **区分**：临时「结束这次协助」后长久码仍有效；仅当用户在确认窗显式勾选「一并撤销长久码」时才一并作废（默认不勾）。  
7. **安全**：不引入 ownerLink/设备密钥；不削弱 `tls-trust.md`；短码可连仍等 R050。  
8. **交互**：本文件无逐字按钮稿；体验出的交互稿须与用户确认后再锁文案。

## 不做

- 完整远程桌面 / 键鼠注入  
- 账号免密、设备密钥、服务器 token 授权控制  
- 云端代管长久密码明文  
- 默认勾选「无人时写操作不再询问」或未二次确认即生效  
- 结束临时协助时默认顺带撤销长久码  
- 把本条写成 R050 已交付或短码已可安全连接  
- 场景 bot 不出交互像素稿（交给体验）
