## 本轮目标

2. **打磨**：品牌名扫尾 + 首页亲友向文案（体验项 1、2、4）

## A. ownerLink 专项验收

- **用户**：同一账号连接自己已上线的另一台电脑。
- **步骤**：登录 → 设备列表 → 一键连接 → **不出现配对确认窗** → 提议写操作时被控仍弹出确认。
- **验收**：
  1. owner 连接无配对确认窗（审计可见 pair_owner_auto 或同等记录）
  2. 写操作确认仍在，拒绝则不执行
  3. 访客 code+密码 连接仍要配对确认
  4. 中继配对成功不等于获得写权限
- 代码侧 AgentHost 已有 ownerLink 自动授予 Assist 的逻辑；本轮重点是补测试、补 UI 提示（例如「已用你的账号连接，无需再确认配对」），并跑通上述矩阵。

## B. 品牌与首页文案扫尾

1. 协助端、首页、安装包用户可见名称若仍写「远端协助」，改为「鹊桥」或「鹊桥远程协助」。验收：冷启动各主窗口标题含「鹊桥」；用户可见产品名不再出现「远端协助」（日志字段名除外）。
2. 首页页脚：默认只保留「选上面一项即可。」IP、端口、--accept / --control 等收到「高级」。验收：亲友打开首页看不到 IP、端口号、命令行参数。
3. 首页角色卡片：「接受协助（被控）」去掉「（被控）」，说明补上「验证密码」；「去协助别人」把「粘贴对方会话载荷或会话码」改为「粘贴对方发来的会话码和验证密码」。验收：首页不出现「被控」「载荷」「--accept」。
4. 被协助端验证密码不要用红色（像报错），改为与会话码同色。验收：密码看起来不像错误提示。
