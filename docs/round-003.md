# 第 3 轮 — 首屏减负 + 连不上引导

> 产品负责人：鹊桥-产品 · 2026-11-05 Asia/Shanghai
> 实现：鹊桥-客户端（只改 src/，不改中继）
> 状态：**done**（2026-11-05 Asia/Shanghai 实现并截图）
> 依据：鹊桥-体验评审 + 场景 S002（与失败文案合成，不拆两条）

## 本轮目标

1. **高频**：连不上时的可执行引导（两端同一类原因 + 下一步）+ 第一次打开的「请点允许连网」
2. **打磨**：被协助端首屏减负，以及协助端一次粘贴自动填入「会话码+验证密码」

## 原则

- 分两个时刻，同一套话术。
- 亲友主路径不写「放行入站」，不出现端口号（17890 / 17891）。
- 系统弹窗「是否允许访问」不是改防火墙高级设置。
- 全文默认界面不出现 121.196.45.81、relay_guest_*、insecure、明文模式。

## A. 连不上引导

### 时刻 A · 第一次打开（被协助端顶部横幅，系统弹窗出现时）

「请点「允许」，让鹊桥连网。弹窗里也许写着 RemoteAssist.Agent，就是本软件。不用改设置。」

若点了「取消」：「刚才可能点了取消，对方将连不上。」主按钮「打开防火墙设置」，说明「找到本软件（可能叫 RemoteAssist.Agent），勾选允许」。

### 时刻 B · 码已发出但连不上（被协助端运行状态、协助端连接按钮下方，两端同类文案）

- 密码不对：「验证密码不对。请对方再点一次「复制码+密码」发给你，不要只发会话码。」
- 已换新码：「对方已刷新会话，旧码失效了。请对方重新复制并发给你。」
- 到不了中继：「现在连不上网络。请双方检查网络后重试。」（不要写改端口或放行入站）
- 对方还没开始接受协助：「对方还没打开「接受协助」。请对方在首页选择「接受协助」，再把码和密码发给你。」

验收：错密码、刷新后用旧码、断网、对方停在首页未进入接受协助，约 1 分钟内两端能看懂并知道下一步。全文不出现 17890/17891、「放行入站」。

## B. 首屏减负与一次粘贴

1. 本机 IP 与端口收到「高级」。首屏只留会话码、验证密码、主按钮「复制码+密码」。验收：打开「接受协助」后不滚动就能复制；主信息不是本机 IP。
2. 二维码下方「TLS 指纹 / 明文模式 (--insecure)」默认隐藏，调试态只放「高级」。验收：默认首屏不出现 insecure、明文模式、TLS 指纹。
3. 分享区默认只留「复制码+密码」；「复制载荷」「复制 MCP 配置」「复制会话码」放进「更多」。验收：分享区默认只有一个主按钮。
4. 运行状态改为「已连上网络，可以发给对方了 / 等待对方连接」；原始审计收到「高级」。验收：默认界面不出现 121.196.45.81、17891、relay_guest_*。
5. 协助端支持一次粘贴 R001 的两行「会话码：… / 验证密码：…」并自动填入。验收：从微信转发整段粘贴后可直接连接，不必拆开手填。

## C. 协助端断点与访客配对窗（体验/场景补进本轮）

6. 空态不报错：输入框为空、尚未点「连接」时，不要出现「无法连接」或 `remoteassist:pair`。真正连失败后，用时刻 B 的四类白话，不出现 `remoteassist:pair`、载荷链接术语。
7. 一次粘贴验收写清：主输入框粘贴和「从剪贴板」都能解析两行「会话码：… / 验证密码：…」，不只认载荷链接。格式不对时提示「请粘贴会话码和验证密码」。
8. 默认走公网中继，不要默认端口 17890（那是局域网高级路径）。配对区默认只留粘贴框 +「从剪贴板」+「连接」；主机、端口、明文、TLS 指纹、权限级别放到「高级」。
9. 访客配对确认窗（从原 R004 并入）：
   - 标题：「有人想协助这台电脑」
   - 正文：「对方可以查看进程、日志和文件，不能直接改你的电脑。真正要改动时，还会再问你。」
   - 按钮：「允许协助」/「拒绝」；超时自动拒绝，不要自动允许。
   - 验收：访客连接必出此窗；ownerLink（自己的设备）不出；全文不出现 Assist、MCP、ownerLink、TLS。写操作确认仍跟 P0，不塞进本轮。

若本轮做不完，保底顺序：时刻 A/B → 空态报错 + 两行粘贴 + 默认走中继（不要 17890）→ 访客配对窗白话 → 被协助端首屏减负 → 协助端其余字段进「高级」。
