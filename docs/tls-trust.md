# 业务 TLS 与短凭证信任模型

> 产品拍板：2026-11-06 Asia/Shanghai（R043 安全纠错）  
> 架构落点：本文 + `architecture.md` §15；协议侧约束见 `relay-protocol.md`「安全与产品约束」。  
> **不改中继协议字段**；指纹是业务 TLS 客户端钉扎，不是中继控制面字段。

## 结论（必须遵守）

1. **默认公网中继**（现网见 `relay-deploy.md`，默认 `121.196.45.81:17891`）：客户端**内置 / 随版本发布**官方业务 TLS 证书指纹钉扎。人话短凭证 `{会话码}-{8位验证码}` **只授权会话**（对应 `guest_join` 的 code + password），**不携带指纹**。
2. **自定义中继**（用户改了中继地址，或非官方默认端点）：必须提供**完整安全载荷**（`remoteassist:pair…` 且含 `fp=`）或等价**显式配置**（设置里填指纹 / `--fp` / 环境变量等）。不得猜测指纹。
3. **禁止 TOFU**（首次见到什么指纹就信什么）。
4. **禁止自动降明文**：不得因缺指纹而 `skipTls` / `Insecure=true` / 明文业务管道。缺指纹 → **安全阻断** + 人话提示；`--insecure` **仅显式调试**，不可作为公网主路径或短凭证的隐式回退。
5. 中继仍只做 JSONL 控制 → 透明 pipe；**业务 TLS 端到端**，中继不终结、不解析业务帧。本模型**不要求**改现网中继部署或 `guest_*` 字段。

## 两条路径怎么取指纹

| 路径 | 会话授权 | 业务 TLS 指纹来源 |
|------|----------|-------------------|
| 默认公网中继 + 短凭证 / 旧两行码+密码 | code + password | 客户端内置官方指纹（与默认中继地址绑定；随发版更新） |
| 默认公网中继 + 完整 `remoteassist:pair` 载荷 | 载荷内 code/pwd 等 | 载荷 `fp=` **优先**；若无 `fp` 则回退内置官方指纹；仍无则阻断 |
| 自定义中继 | 同上 | **必须**载荷 `fp=` 或显式配置；**不得**用「官方内置指纹」顶替 |
| 局域网 `via=lan`（高级/调试） | 既有 LAN 约定 | 完整载荷含 `fp=`，或显式 `--insecure` 调试 |

「是否默认公网中继」以客户端识别为准：地址等于文档/设置中的**官方默认中继**（可随发版与 `relay-deploy.md` 对齐）。用户改成其它 host:port → 按自定义中继处理。

## 与短凭证规范的关系

- 展示与复制形态见 `quality-connection-credential.md`。
- 短凭证**故意不带**指纹，避免亲友口令过长；安全靠「默认中继 → 内置钉扎」。
- 完整安全载荷（含指纹）仍保留给 MCP、二维码、自定义中继、高级粘贴。

## 实现约束（客户端；不改 relay/）

- 协助端在启用 TLS 且指纹缺失时：**抛错 / 人话阻断**，禁止静默 Insecure。
- 被控端在默认公网中继路径上，业务证书须与**同版本官方指纹**一致（对齐既有 net8 Agent 发证 / 载荷做法，不要新发明旁路通道）；自定义中继或完整载荷路径继续把真实 `fp` 放进载荷。
- net8 Helper「无指纹 force Insecure」记为已知债，**另开轮**修；不得在 R043 短凭证路径上再扩大该行为。
- 完整连接凭证与指纹**不得**写入普通日志 / 对外异常原文。

## 与现网部署对照

| 项 | 结论 |
|----|------|
| 生产中继 `121.196.45.81:17891` | **无矛盾**。控制面仍为 TCP JSONL；pipe 仍 opaque。 |
| 安全组仅 TCP 17891（+ 官网 80） | **无矛盾**。本模型不引入中继侧 TLS 终结。 |
| smoketest 只验配对 + 管道透传 | **无矛盾**。业务 TLS/指纹是客户端验收项。 |
| 中继协议字段 | **不新增**；短凭证仍拆成 code + password。 |

## 变更流程

改官方默认中继地址或轮换官方指纹：先更新本文 + `relay-deploy.md` / 发版说明，再改客户端内置钉扎并发版；旧客户端在轮换后会因指纹不匹配而阻断（预期），需升级。
