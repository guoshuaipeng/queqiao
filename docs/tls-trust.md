# 业务 TLS 与连接凭证信任模型

> 产品拍板：2026-11-06 Asia/Shanghai（安全纠错；**废止**「默认中继内置官方指纹」设想）
> 架构落点：本文 + `architecture.md`；协议约束见 `relay-protocol.md`。
> **不改中继协议字段**；指纹是业务 TLS 客户端钉扎对象，不是中继控制面字段。

## 结论（必须遵守）

1. **业务 TLS 端到端**：钉扎对象是被控端**进程内临时自签业务证书**（SHA-256 指纹），经完整载荷 `fp=` 分享。协助端按该指纹校验，不匹配即断开。
2. **中继不终结业务 TLS**：生产中继（见 `relay-deploy.md`，默认 `121.196.45.81:17891`）控制面为 **明文 TCP JSONL**，配对后 **opaque pipe**；中继无业务证书、无业务 TLS。**禁止**「客户端内置官方中继 / 官方业务指纹」方案——仓库无此常量，且钉错身份。
3. **「复制连接凭证」= 完整安全载荷**：一次复制必须含会话码 + 密码 + **Agent 业务指纹**（`remoteassist:pair` 形态）。
4. **短「会话码-8位验证码」仅展示/口述**：不能单独完成安全连接；协助端若识别到无 `fp` 的短码或旧两行 → **阻断**，人话引导对方重发完整凭证。
5. **禁止 TOFU**（首次见到什么指纹就信什么）。
6. **禁止自动降明文**：不得因缺指纹而 `skipTls` / `Insecure=true` / 明文业务管道。缺指纹 → **安全阻断**；`--insecure` **仅显式调试**，不可作主路径回退。
7. 自定义中继 / 非默认端点：同样依赖载荷内 `fp=` 或等价显式配置；**不得**用「官方内置指纹」顶替。

## 两条路径怎么取指纹

| 路径 | 会话授权 | 业务 TLS 指纹来源 |
|------|----------|-------------------|
| 完整 `remoteassist:pair` 载荷（主路径「复制连接凭证」） | 载荷内 code / pwd | 载荷 `fp=`（Agent 业务证）；缺则阻断 |
| 短码 `{码}-{8位}` / 无指纹旧两行 | 可识别 code+password | **无指纹 → 阻断连接**（不进入业务 TLS） |
| 局域网 `via=lan`（高级/调试） | 既有 LAN 约定 | 完整载荷含 `fp=`，或显式 `--insecure` 调试 |

## 与现网部署对照

| 项 | 结论 |
|----|------|
| 生产中继 `121.196.45.81:17891` | **无矛盾**。控制面仍 TCP JSONL；pipe 仍 opaque。 |
| 安全组 TCP 17891（+ 官网 80） | **无矛盾**。不引入中继侧 TLS 终结。 |
| 中继协议字段 | **不新增**；完整载荷在客户端解析后仍拆 code + password 做 `guest_*`。 |
| 「内置官方指纹」 | **已废止**；勿再写入产品/架构文档或客户端常量。 |

## 实现约束（客户端；不改 relay/）

- 「复制连接凭证」须调用与二维码/载荷相同的安全构建路径（含当前 Agent `fp`）。
- 协助端启用 TLS 且指纹缺失：**人话阻断**，禁止静默 Insecure。
- 完整连接凭证与指纹**不得**写入普通日志 / 对外异常原文。

## 短凭证主路径（目标，R050 blocked）

亲友主路径目标只复制「会话码 + 8 位验证密码」；业务 TLS 仍钉被控 Agent 临时业务证书 fp，**禁止无 fp 连接**。强化目标：服务端不知明文密码且不可冒充（成熟 PAKE，禁止自造密码学）。R050 **未授权实现**，未落地前仍沿用既有「缺 fp 阻断」；产品意图见 `PRODUCT.md`，状态见 `roadmap.md`。
