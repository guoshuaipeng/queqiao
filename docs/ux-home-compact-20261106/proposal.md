## 1. 问题（为何上版不算紧凑）

壳客户区远高于首页内容带时，若只拉宽卡片、高度仍钉死，卡底到脚注会留下百余 DIP 空灰（默认约 130、宽窗约 220）——与用户「留白太多」同一抱怨。本版改为 **两卡等分可用内容高度**，卡底→脚注仅 **16–24 DIP**。

证据（评审用，不印图上）：`ShellMainForm.cs` L35 共用 `780×780`；`ModeSelectForm.cs` L24/L60/L68 绝对坐标按 560 宽布局。

## 2. 客户区尺寸（DIP）

| 场景 | 客户区 |
|------|--------|
| 首页**首次展示**默认 | **640×360** |
| 窄参考 | **520×340** |
| 宽参考 | **780×440** |

**首页首次可用上表默认；不得把壳全局永久缩到该尺寸以致破坏其他业务页。** 进入接受协助 / 协助端：保留各页现有最小尺寸或按该页布局适配（见 §5 检查）。默认尺寸为逻辑建议，非实测。

## 3. 纵向分配规则（必须）

固定带（约）：

| 带 | DIP |
|----|-----|
| 顶栏 | **64** |
| 顶栏下内容上边距 | **16** |
| 左右边距 | **20** |
| 两卡间距 | **12** |
| 卡底 → 脚注 | **16–24**（预览取 20） |
| 底部说明区 | **32–36**（预览取 34） |

**中间剩余高度由两张入口卡等分**（预览取值）：

| 窗 | 单卡高（约） |
|----|--------------|
| 默认 640×360 | **100** |
| 窄 520×340 | **90** |
| 宽 780×440 | **140** |

验算（默认）：64+16+100+12+100+20+34 = **346** ≤ 360（余量落入边距容差，**不**堆到卡脚之间）。

卡片内部：标题+短说明为一组**垂直居中**；右侧仅 **›** 垂直居中。不添加功能块填白。

**拖高窗口时**：额外高度继续等分给两卡，可设合理最大卡高；超过后整体内容块在客户区内垂直居中，**不**把多余高度默认堆成底部大空，也**不**默认打开超高窗。工作区不足（如 200% DPI）时先适配可用工作区，内容区可纵滚保入口可达；最小逻辑尺寸不得硬顶出屏。

**拖拽缩放：建议启用，待用户确认**（纳入本方案确认范围）。宽变时顶栏/双卡随宽拉满（左右边距固定）。
