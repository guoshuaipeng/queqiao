# 鹊桥官网竞品内容结构调研与实施依据

调研日期：2026-11-06（Asia/Shanghai）
状态：研究建议，供体验/产品全员评审；不是已完成改版、实现授权或上线授权。

## 方法与边界

实时读取向日葵、TeamViewer、ToDesk、AnyDesk、RustDesk五家公开首页、下载与相关支持页；这是目的性样本，不代表“市面上大部分产品”。用WebFetch读取正文，并用公开HTML核对向日葵、TeamViewer、ToDesk、RustDesk导航自身链接。AnyDesk首页HTML请求403，但WebFetch正文和Windows下载页可读取，下载链接另经搜索确认。不使用登录态、不接触第三方账户。

只核查内容与链接结构，没有视觉浏览、截图或移动视口操作。因此不评价颜色、布局像素、实际首屏位置、按钮视觉突出程度、折叠菜单可用性或移动端已通过。正文提取不包含的内容不等于页面不存在；ToDesk下载具体版本列表、向日葵动态版本字段尤其不能据此判缺失。

未调查鹊桥本地仓库、用户机或生产站；现有资产由服务端另行提供。所有“鹊桥建议”都是目标结构，不是当前网站缺陷断言。

## 逐家事实、可复用点与不可照搬点

### 1. 向日葵：场景分层明确，但内容面向成熟企业产品

- 首页主张为“全企业场景的远程IT运维解决方案”，按IT运维、技术支持、远程办公等分层，后续列能力、安全与行业案例。[S1]
- 官网导航同时提供“下载”、个人版下载、“帮助文档”“安全守护”；下载页明确个人Windows安装后可发起和接受远程控制，并把企业控制端写为“安装在管理远控的设备”、企业客户端写为“安装在被控制的设备”。[S1][S2]
- 帮助页能查安全设置、连接端口、安装依赖、不同系统使用手册及SOS手册。[S3]
- 可复用：用自然语言讲清双方角色；下载、使用说明、故障处理形成闭环；能力后面接可查证的安全说明。
- 不照搬：多产品矩阵、硬件商城、私有化、行业案例墙、注册/设备规模数字及认证。鹊桥不能借这些模块暗示同等成熟度。
- 鹊桥落点：亲友协助主场景；“我需要帮助 / 我要帮助别人”的教程分支，但同一个已验证Windows包，不制造两个假客户端。

### 2. TeamViewer：商业首页与实际下载/接收支持说明分工

- 本轮首页正文重点是Tia/AI、企业案例、集成、安全证明与业务咨询，不再是单一“远控下载”内容。[S4]
- 自身导航有Personal use、Small businesses、Free Download、Knowledge Base和System status。[S4]
- Windows下载页写明provide or receive support；FAQ区分完整客户端与QuickSupport：前者提供支持，后者轻量、免安装、临时接收支持；同时解释个人/商业使用边界、旧版本与安全。[S5]
- 状态页区分服务组件、维护、事件和恢复，证明“连不上”可以有服务端解释入口。[S6]
- 可复用：把“该下载什么、给谁用、装不装、如何结束”和使用边界放在用户能找到的地方；支持页不只留联系方式。
- 不照搬：AI代理、行业头部客户、企业安全认证和复杂套件。状态页也不能由静态绿色“正常”伪装实时监测。
- 鹊桥落点：官网先服务首次使用，不先搭销售平台；状态入口只有接入真实监测/人工维护流程才上线，否则标明暂无公开状态页。

### 3. ToDesk：按用户类型和用途分流，但不宜复制复杂版本导航

- 首页和导航把个人、团队、企业分开；又区分远程支持、办公、游戏、协作、文件传输、手机等场景。首页描述SOS绿色被控端、企业部署和日志管理。[S7]
- 官网自身导航链接到个人下载、企业下载、个人帮助中心、企业帮助中心；下载页可读出个人/企业账号体系区别，但具体下载项正文提取有限，不能声称某个Windows入口不存在。[S8]
- 帮助中心正文列视频教程，包含临时技术支持SOS连接。[S9]
- 可复用：按“用户现在要完成什么”组织帮助；下载旁就有适合新手的说明。
- 不照搬：游戏/设计/性能/团队/企业等大矩阵，8K、360帧、低延迟和用户好评/规模数字。厂商营销主张不是本次独立性能测试结论。
- 鹊桥落点：不改用户尚未确认的产品定位，不把小微付费研究结论直接替换亲友主场景；技术支持只可作为次级用途介绍且能力须核实。

### 4. AnyDesk：具体下载元数据与完整开始—结束教程

- 首页正文按Collaboration、Assistance、Access、Security解释收益，并给技术支持/访问等需求分流。[S10]
- Windows页明确显示v9.8.3、8.6MB、Changelog、操作系统范围与下载使用条款；这是该站本轮显示值，不可复制为鹊桥数据。[S11]
- Quick Start Guide分别讲下载、安装/便携方式、开始会话与本机/远端结束会话；还把高级管理员配置放到后面。[S12]
- 可复用：下载包身份可核查；教程有结束步骤，不止“开始连接”。
- 不照搬：快速指南含无人值守设置，鹊桥未确认此能力，不能直接沿用；也不能复制TLS/端到端隐私承诺。
- 鹊桥落点：下载卡明确实际包版本、日期、大小、系统/运行时要求、校验值、签名状态、发布说明；结束后凭证是否失效必须先统一现有产品口径。

### 5. RustDesk：单一核心差异贯穿，但安装方式明显面向技术用户

- 首页核心是开源、自托管、数据控制；开头明确唯一官方域名并提醒不要从其他域名下载。下方给Docker自建步骤与项目/社区证据。[S13]
- 自身导航Download指向项目正式release；官网/download本轮跳转/返回release内容，按架构和系统列Windows EXE/MSI、Legacy等及变更日志。[S14]
- 支持页明确其邮件问题支持针对Server Pro。[S15]
- 可复用：一个可信差异讲透；官方来源和版本变化可追溯；支持范围不含糊。
- 不照搬：把Docker或GitHub复杂资产列表作为长辈主下载入口；开源、自建、星数和用户调查都不能用于鹊桥背书。
- 鹊桥落点：普通用户只看一个Windows推荐入口；技术信息折叠至详情，不把选架构/找文件的成本留给亲友。

## 8条跨站发现 → 鹊桥可实施要求

1. **不是所有首页都应像大厂企业站。** 向日葵/ToDesk/TeamViewer都有企业化首页；鹊桥目前亲友优先，不应照搬企业套件巨页。[S1][S4][S7] 建议导航限“如何使用 / Windows版本 / 帮助 / 安全与隐私”。不按未确认定位改成企业售卖站。
2. **讲清双方比堆功能更重要。** 向日葵下载说明、TeamViewer QuickSupport FAQ都明确角色。[S2][S5] 建议“需要帮助的人”和“来帮忙的人”各3步，附“双方使用同一Windows包”（须服务端确认）。这是教程分支，不是要求客户端恢复首页选角色跳转。
3. **一个下载按钮还不够，包身份必须可查。** AnyDesk给版本/大小/changelog，RustDesk按发布与架构追溯。[S11][S14] 建议下载卡由同一发布元数据驱动首页/下载页；正式包与开发版分开；不允许旧包配新UI截图。
4. **下载状态应与验收状态绑定。** 竞品成熟承诺不能借用。鹊桥若暂无经授权公开的包，主行动用“查看Windows试用说明”，不要放空下载、假按钮或未经许可扩大发放；有包再明确“试用版/已知限制”。
5. **信任要靠可核查事实，不靠盾牌装饰。** 大厂列安全说明、认证、客户证据；RustDesk强调官方域名。[S1][S4][S13] 鹊桥先列版本、来源、真实隐私政策、已验证授权/结束行为及已知限制；R050 blocked，禁写“已满足严格唯一凭证/零风险/绝对安全”。
6. **失败恢复是官网主路径一部分。** 向日葵帮助列端口与依赖、ToDesk有教程、TeamViewer有真实状态页。[S3][S9][S6] 鹊桥首批FAQ覆盖下载/安装、运行时、完整凭证、网络与连接、权限拒绝、断开/重连、卸载；提示不能教用户关闭杀软或随意绕过系统拦截。
7. **教程必须有结束和退出。** AnyDesk具体列双方结束会话。[S12] 鹊桥应解释本机如何停止协助、撤回权限，以及结束与刷新凭证的区别；当前作废规则冲突先收口再写，禁止替产品拍板。
8. **移动端可读性本轮没有视觉证据。** 五家可读正文不代表小屏可用。鹊桥必须另测手机访问→辨认Windows包→看到“请在Windows电脑打开/下载”→无需登录可读教程。禁止把Windows下载标成手机可安装，禁止把拟议客户端双区设计渲染成已发布截图。

## 建议内容骨架（待体验细化及全员评审）

### 首段：是什么、给谁用、现在到哪一步

建议标题：`帮亲友处理电脑问题，少一点来回解释。`
建议说明：`鹊桥是一款以 Windows 为主的远程协助工具，目前处于试用验证阶段。使用前请先查看支持范围与使用说明。`
不写“全自动修好”“全平台”“秒连”“永久免费”“商用级安全”。标题中的价值是产品意图，不是效果量化承诺。

主行动：若无已授权发布包，`查看 Windows 试用说明`；若有则`下载 Windows 试用版`，旁边显示版本/发布时间/文件大小/已知限制。
次行动：`第一次怎么用`。
不强迫选角色才能下载；两角色说明就在同页可找到。

### 角色说明

- 需要帮助：打开软件 → 把完整连接凭证私下发给认识的帮助者 → 核实请求并在本机允许。
- 帮助别人：打开软件 → 粘贴对方完整连接凭证 → 等待对方允许。
- 共同提醒：只与信任的人建立协助，不把凭证贴到公开评论、聊天群、截图或故障日志。

以上步骤须用实际验收版本校准；不能退化为短码即可安全建连，也不公开带有效秘密的示例。

### 安装/来源与信任说明

- 支持的Windows版本与32/64位必须从实际包验收结果获取，不能因net48就推定支持所有老系统。
- .NET Framework依赖、管理员权限要求、安装目录、快捷方式、系统卸载入口分别说明。
- 安装版与解压/开发运行版明确区分，后者不伪称可在系统应用列表卸载。
- 代码签名仅按实际状态写：未签名不能展示“已认证”；校验值不能冒充签名。
- 软件截图只能取实际版本、移除真实凭证；原型必须标“交互方案，非已发布界面”。A一屏双区尚在细化，不能当正式截图。

### 帮助与限制

先做可读短FAQ和可达反馈入口，不承诺尚不存在的7×24客服、在线工单或状态监控。安全说明、隐私政策、用户协议须与实际数据收集/保存/中继事实一致，不套用竞品模板。

## 本地实现后的验收清单（研究方建议，非本轮已执行）

- 全员评审留记录；每个可见承诺有能力/验收/授权证据，未回复不算通过。
- Windows下载链路对应真实包；版本、hash、大小、日期一致；失败显示可理解提示，无假下载。
- 首次用户不靠开发者解释能找到正确Windows入口并分清双方步骤；不能错误理解为浏览器直接控制或AI自动修复。
- 375px/390px手机、平板、常用桌面视口；200%缩放；键盘Tab/焦点、对比度、触控目标、无水平溢出；这些都是待实测，不得先PASS。
- 手机访问能读教程，不因识别非Windows而隐藏信息；无需扫码作为唯一入口。
- 不用伪造“绿色正常”状态；未接监控时保留状态能力待办。
- 安装/卸载、凭证、权限、失败/恢复FAQ与真实客户端版本一致。
- 不增加用户追踪、营销收集表、第三方脚本或自动下载；这些需另行决定数据与隐私边界。
- 当前仅给本地改版提供依据：不push、不上线、不部署、不扩R049/R050安全授权。
