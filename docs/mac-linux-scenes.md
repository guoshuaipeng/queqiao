# Mac / Linux 场景闭环

> 产品收口：2026-11-05 Asia/Shanghai。场景写三类用户闭环，体验写安装说明 / CLI 展示 / 终端确认原文（待补），产品合并写入。
> 不改 R009：R009 仍是 Linux 可运行的被控 CLI + MCP + 终端确认，以及框架依赖小包。亲友和客户的完整主路径以下一阶段 Avalonia 被控窗为准。
> 信任等级不另写文案，沿用 docs/trust-levels.md。

安全底线与 Windows 相同：默认走公网中继；访客用会话码 + 验证密码；写操作必须在被控本机确认；不做完整远程桌面 / 键鼠注入；访客只读仍是天花板；完全信任只对当前会话和当前这位协助者有效；审计留在被控本机。界面不出现 Assist、Admin、ownerLink、TLS、端口号。发给协助方的仍是两行「会话码：… / 验证密码：…」，Windows 协助端一次粘贴可用。

## 和 Windows 的差异

- **启动**：先按说明装好 .NET 8（若需要），再打开对应包。macOS 是 `.dmg` 拖进应用程序；Linux 先 `.tar.gz`（随后可选 `.deb`）。不要套 Windows「点允许连网」的话术。macOS 可能要在系统设置里仍允许打开；Linux 可能要先给执行权限。Avalonia 第一阶段只要被控窗，不要求对等的「去协助」。
- **出示凭证**：被控窗提供和 Windows 一样的「复制码+密码」，不要让亲友去终端里手选。
- **写确认**：同样弹本机窗，语义与 Windows「对方想在这台电脑执行操作」对齐；允许才执行，拒绝则未做任何改动，超时不自动允许。
- **收尾**：Mac / Linux 用户更常把关窗当成退出。要写清关窗不等于结束协助，并提供明确的「结束这次协助」；刷新会话码后旧码旧密失效。

## 谁先用哪一种形态

- **同事运维**：R009 的 CLI 可先跑通（会用终端的人）。
- **亲友协助、客户支持**：不要把「打开终端复制码」写进主路径；完整闭环等到 Avalonia 被控窗。

## 亲友协助

- 用户：家人用 Mac 或 Linux，不会用终端。协助方仍可以在 Windows「去协助」。
- 场景：把安装包或官网说明发给家人，家人出示会话码和验证密码，协助方连上排查；危险操作在家人这台电脑上确认。
- 步骤：按官网说明安装（含必要时先装 .NET 8）→ 打开被控窗 → 复制码+密码发给对方 → 访客需本机点「允许协助」→ 写操作本机确认 → 结束这次协助或刷新会话码。
- 验收：不打开终端也能从安装走到收尾；两行文本能被 Windows 协助端一次粘贴；拒绝写操作后未做任何改动。

## 客户支持

- 用户：客户的 Mac 或 Linux，修完要能交代改了什么。
- 场景：与亲友同一条访客路径；客户要能在本机看到这次已确认的改动。
- 步骤：与亲友同一条访客路径；审计仍在客户本机，不另做工单。
- 验收：客户不进终端也能出示凭证并确认写操作；本机审计能看到本次已确认的写操作。

## 同事运维

- 用户：同一账号连自己的或同事的 Mac / Linux。
- 场景：会用终端的人可以先用 R009 CLI 连上；有被控窗之后，被控侧用窗出示码或账号上线。
- 步骤：R009 的 CLI 可先跑通；Avalonia 被控窗阶段，被控侧用窗出示码或账号上线。协助方免密连时跳过配对窗，写确认仍受信任等级约束。
- 验收：owner 连接无配对窗；写操作仍按信任等级询问；访客不能因为本机开了完全信任而获得写权限。
