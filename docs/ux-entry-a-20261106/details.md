## 2. 统一外框与布局预算

### 2.1 基线和适配

| 项目 | 设计值/规则 |
|---|---|
| 所有状态默认客户区 | **840×480 DIP**；不含系统标题栏和边框 |
| 并排 → 上下堆叠 | 可用客户区宽 **<760 DIP**；按可用宽判断，不按物理像素判断 |
| 常规拖拽最小参考 | **640×360 DIP**，仅常规下限，不得阻止首次工作区限幅；小工作区可以低于此值 |
| 用户手调 | 允许；切态保留当前实际尺寸，不重置回默认 |
| 首次启动 | 仅首次按当前可用工作区限幅，计入非客户区；工作区优先于常规 min |
| 自动改窗 | 全链禁止切页/事件回调自动改宽、高；只有首启限幅及用户手调可改变 |

840×480 是统一设计预算，不是给每态强制重置窗口的命令。用户拖小后会话也保持小窗，改内部布局/滚动。

### 2.2 入口：紧凑内容节奏，不拉伸巨卡

840 宽：左右各边距24，中缝16，双区各388（(840−48−16)/2）。顶部用途说明约60；双区顶部约80，内容型区块高约244–252；下方短真实说明约84（含间距），底部保留自然呼吸。卡片不随客户区高度无限拉伸。

- 页头：`鹊桥` + `亲友之间，发凭证或粘贴连接。`
- 左区 `请人帮我`，右区 `我帮别人`，同等层级，按钮靠近各自说明。
- 下部不是灰色剩余容器：白底、细分隔线，两段短流程说明：`请人帮我：开启 → 发凭证 → 等对方连接`；`我帮别人：粘贴完整凭证 → 点连接`。
- 安全短句：`只把连接凭证私下发给你信任、愿意请其帮忙的人。` 不新增勾选、链接、折叠或其他交互。
- 字体正文建议14–16 DIP，主标题20，区标题18，状态不能只靠颜色。按钮建议高36–40，不降低 DPI 下可读性。
- 初始、等待、右连接中均沿此节奏。等待凭证区域有独立视觉界限，不把凭证拉成长空卡。
- **不以补内容填满每个像素**；允许适量留白，拒绝大片灰背景或拉伸巨卡；按全态真实截图综合评审。

### 2.3 会话：480 高预算

| 垂直区域 | 840×480 默认预算 | 规则 |
|---|---:|---|
| 顶状态 | 64 DIP | 对应角色 + 已连接状态；滚动区外，始终可见 |
| 页级内容视口 | 352 DIP | 唯一纵向页面滚动；包含首屏信息/主要操作/当前结果 |
| 固定结束栏 | 64 DIP | 滚动区外；结束按钮不随长内容滚走 |

结束栏左右24，按钮高36–40，短提醒 `结束按当前有效性规则处理` 属设计解释；正式用户文案用 `结束本次协助`，不写「永久作废」。按钮执行沿现有确认/结束规则，不新增绕过。

单页滚动宿主可在壳内容区或会话页根，**只能选一处**；顶部和底部为其同级固定区，不能把整个壳 AutoScroll 连结束栏一起卷走。多行输入的文字滚动可保留，但不得再套工具卡/历史结果的第二层页面滚动。

### 2.4 窄屏、200% DPI 与小工作区

- 窄屏示意：入口 **720×480**（用户手调），双区上下排，内容超过视口则一个页级纵滚；切态仍保持当前720×480，不自动加高。滚动条仅为线框示意，不是额外拖拽操作入口。
- 会话窄屏：内容单列；状态和结束栏继续在滚动区外。主要操作入口换行、当前结果随后，历史结果继续同一页滚；禁止硬塞原320工具卡。
- **200% 时840×480 DIP约为1680×960物理像素（尚未含标题栏/边框）**。例如1920×1080屏幕工作区可能放得下，也可能因任务栏/非客户区受限，必须实际测量；1366×768等小工作区通常需首次限幅。
- 限幅按工作区物理尺寸与实际缩放换算，扣除标题栏/边框后得可用客户区；允许低于640×360常规min，**不能被最小尺寸重新撑出屏幕**。不可把840×480当物理像素硬套，也不在切页时再Fit。
- 低高时先保留压缩到内容高度的状态行、固定结束栏，中间剩余空间单滚。状态/结束必须在首屏可达；其余信息可滚。按钮和文字不得因减少高度而裁断。
- 极小工作区到连状态行+结束按钮都不能完整容纳的边界须真实UI核验并报告；不宣称任意尺寸都PASS，不用出屏、盖住结束或缩小字号掩盖。
- 独立配对/允许协助与写确认模态继续沿既有流程；另测200%和小工作区下全文、默认焦点、取消/确认按钮和所属窗定位，不能因主窗固定而忽略模态出屏。

## 3. 左区：显式开启、等待、停止

| 内部状态（不作用户文案） | 用户看到 | 行为/互斥 |
|---|---|---|
| Idle | `未开启接受协助`；`开启接受协助` | 无监听、无活凭证 |
| AcceptStarting | `正在开启接受协助…`；开启按钮禁用 | 留双区；从显式点开启才启动生命周期，算活动 |
| 启动失败 | `没能开启接受协助，请检查网络后重试。`；`重试开启` | 确认清理后非活动；不露出失效/半就绪凭证 |
| Waiting/凭证就绪 | `等待对方连接`；`把连接凭证发给来帮你的人。` | 留双区；已监听算活动；**必须**有`复制连接凭证`和`停止接受` |
| 停止中 | `正在停止接受协助…` | 保留生命周期归属，阻止重复动作/新角色启动 |
| 停止失败 | `没能停止接受协助，请重试。`；`重试停止` | 不回Idle，不假称已停；保持原活动归属和安全显示规则 |
| 配对且业务会话建立 | `正在接受协助 · 已连接` | 才进Accept业务页，外框不变 |

- 停止成功、确认本地监听和旧等待清理完成，才回Idle，不继续显示活凭证。**不承诺现行凭证永久作废**。
- 用户帮助用 `开启后，把完整连接凭证发给对方，再等待对方连接。`；不显示「中继」「Waiting」「client」「attempt」等技术词。
- 示例载荷只用 `演示占位 · 非连接凭证`，不造可用pair/fp/密码；正式复制仍为现行完整pair（含fp）。
- 复制成功反馈/三秒状态非本项新增必做，可沿现状；不另开P1实现。
- 开启成功若已过期：不能重新展示凭证/恢复监听；关闭迟到资源并按现有通道停止误开的监听。不假称服务端支持撤销。

## 4. 右区：输入、显式连接与失败

| 状态 | 文案/行为 |
|---|---|
| 空输入 | `粘贴连接凭证`；`连接`禁用；不自动读剪贴板、不联网 |
| 有输入但未点击 | 可编辑；不自动发起连接；粘贴不代表同意连接 |
| 点连接后本地校验失败 | 格式错：`连接凭证格式不对，暂时连不上。请让对方重新复制后原样发来。`；不完整/缺fp：`连接凭证不完整，暂时无法连接。请让对方重新复制完整连接凭证后再发。`；不联网 |
| 连接中 | `正在连接对方…` + **`取消`**；左必须已停用，不得左活监听+右连接中 |
| 建连失败 | `没能连上，请检查网络后重试。`；拒绝/配对失败沿既有分因提示，不混为格式错；重试需显式点连接 |
| 取消 | 立即使该attempt失效；UI表明停止中/已取消须与清理阶段一致；清理完成回可编辑，不自动重试 |
| 业务建立 | `正在协助对方 · 已连接`；进入Helper业务页，外框不变 |

完整pair含fp主路径，禁止short-code-only放行。网络错误只能在实际发起后出现，不做点连接前网络预判挡用户。

### Helper取消与迟到回包（保留硬项）

1. 发起尝试起即可取消，**不依赖client已创建或非null**。
2. 每次尝试有attempt世代；取消立即作废当前世代。新显式尝试使用新世代，旧回调不能覆盖较新UI。
3. 迟到成功不进会话、不恢复已取消尝试、不改已连接状态；**关闭迟到成功资源**，按现有安全通道清理半开连接，不能只忽略回调却保留活连接。
4. Disable、对侧禁用或窗口失活不是取消；只有显式取消或确认切换的停止流程才取消。
5. 未完成旧资源清理不得启新角色。清理失败明确阻断并可重试清理，不用回Idle/重试连接掩盖残留。

## 5. 单角色互斥与切换

活动覆盖左Starting、Waiting、Connected；右Connecting、Connected，以及其停止/清理过程。**查看**另一区信息不暗断、不切角色。

- 任一活动侧存在，对侧执行性动作先确认；默认焦点/默认按钮=**取消**，Esc取消，Enter不得误绑定停止/结束并切换。
- 非会话文案：`切换会停止当前操作。取消将保持现在的状态。` 按钮`停止并切换` / `取消`。
- 会话文案：`切换会结束当前这次协助。取消将继续当前协助。` 按钮`结束并切换` / `取消`。
- 确认后先使旧开启/连接世代失效，停止监听/取消连接/结束旧会话并完成旧等待清理，**成功后才启动新意图**。
- 清理/断开失败留原活动归属，提示重试，阻断目标动作；不能标成已停或双角色并行。
- 取消确认保原状态，不停止旧流程。不新增业务页切角色入口；未来若已有切换动作映射，仍遵守此规则。
- 真配对确认+业务会话建立之前，不把Waiting或仅Paired事件当Connected。具体事件聚合映射待客户端核对。

## 6. Accept真实会话布局（`accept-session.svg/png`）

此处画的是**业务会话态的设计线框**，不是真实运行截图；不是新的Waiting就绪条。

- 顶固定状态：`正在接受协助` + `已连接`（文字+颜色，不能仅绿点）；首屏明确对方连接状态。
- 滚动区首段：`对方已连接`，同时提示 **`请核对对方身份，不要默认信任对方。`**。提示不新增信任切换控件、不改变当前本机信任档/授权逻辑。可显示哪些身份字段待客户端映射，不捏造姓名、设备名或已验证身份。
- 其余既有会话信息置于同一内容流；未知字段以设计占位框标注，**不可将占位原样上线**。不增加监听开关、会话历史、自动信任或无人值守入口。
- 结束栏固定在滚动区外，`结束本次协助`始终可见。**本机确认结束 → 按现有通道清理本地连接/监听和旧等待 → 全部清理成功后回Idle**；再次接受协助必须由本机显式点击`开启接受协助`，不自动恢复监听。失败或未清完保持活动归属，不伪装Idle，提示重试清理；不承诺连接凭证永久作废。若现有通道无法完成清理，必须回产品收口，不能自行降级、绕过或改协议。

## 7. Helper真实会话布局（`helper-session.svg/png`）

- 顶固定：`正在协助对方` + `已连接`。
- 首屏按顺序：**既有主要操作入口 → 当前结果/空态**。保留当前业务操作，不编造命令/远控模式/工具。主要入口槽位按可用宽自动换行，不能把现320工具卡连同固定尺寸硬塞进新壳。
- 当前结果与历史结果属于**同一页级滚动流**；初始设计空态用 `尚无本次操作结果`（最终需映射真实结果语义）。长历史接在当前结果下，不给历史单独套页面滚动，也不造模拟执行记录。
- 结束栏固定在滚动区外，不能被历史顶走。结束与返回统一沿§6末段：本机确认结束，按现有通道清理本地连接/监听和旧等待，成功才回Idle；失败/未清完保活动并可重试清理。再次接受须显式开启，不自动重新连接/恢复监听，不承诺码永久作废；现有通道无法清理须回产品，不自行降级或改协议。
- **待客户端映射清单**：现有主要按钮名称/顺序/状态/控件ID，当前结果字段/空态来源，历史是否现有及数据呈现，现320工具卡内部最小尺寸，键盘顺序与忙碌互斥。以上未核对前，不得宣称业务页已适配或首屏预算已实测通过；若实测入口和当前结果仍不可达，反馈产品**统一调整全态预算**，禁止仅业务页自动加高。
