# S005 — 协助方中途断线人话与重连引导

> 场景：鹊桥-场景 · 2026-11-06 Asia/Shanghai  
> 状态：需求已写入；**R043 已开实现**（见 `docs/round-043.md`），交给鹊桥-客户端。  
> 约束：不碰 macOS 正式下载、HTTPS、完整远程桌面；本条**不要求**新增中继协议字段；不改 R003 未连上失败句、不改 EndAssistCopy。

## 结论（选哪条断点）

三条闭环里，**亲友协助 / 客户支持在「已连上之后」仍高频断在中途掉线**：Wi‑Fi 闪断、对方电脑休眠、中继抖一下，协助端一律写成「对方已结束这次协助。」，并清空失败提示。亲友会以为对方主动关了、不敢再点连接；实际对方往往仍在「接受协助」等着重连。  
R035 曾写「网络中途断开也可以用对方结束句、不必区分」——稳定与体验优先后，这条要收紧：**仍可不区分「对方点了结束」还是「传输断了」（无新协议字段）**，但文案与下一步要从「对方结束」改成「连接已断开 + 可怎么重连」。

不选「只读结果区控制台味」作本条：R041 缺口已记，属打磨；本条先修掉线后人话与重连闭环。

## 用户 / 场景

- **用户**：亲友协助方、客户支持（去协助端；Windows `Helper.UI` 与 Avalonia `HelperWindow`）。
- **场景**：已成功连上 → 会话中途底层传输断开（非协助方自己点断开）→ 需要知道发生了什么、能不能再连。
- **现状断点**（对照源码与 `docs/round-035.md`，2026-11-06）：
  1. `AssistClient.ConnectionLost` 后两端都 `SetStatus(HelperSessionCopy.StatusPeerEndedAssist)`（「对方已结束这次协助。」），并 `ClearFailHint()`——**意外中断与对方主动结束同一句，且无下一步**。
  2. 对方若只是网络闪断、仍在接受协助，同一码往往还能再连；UI 却像「别再连了」。
  3. 若断在工具调用中，`RunToolAsync` catch 可能先露出「调用失败：Connection closed…」类原文，再被 ConnectionLost 盖掉或并存，亲友路径不友好。

## 步骤（可开发需求）

1. **已连上后、非自己点断开的会话消失**  
   主状态改为人话（建议锁定）：**「连接已断开。」**  
   不要再用「对方已结束这次协助。」覆盖这类 `ConnectionLost`（该句可保留常量，但本条场景不再作为中途掉线主状态；若产品仍要在「对方明确点了结束」时用旧句，须另开协议原因字段——**本条不做**）。

2. **同屏给出重连引导（失败提示区 / 次要行，人话一句即可）**  
   建议锁定：  
   **「若对方仍在接受协助，可再点「连接」；若对方已结束，请对方重新打开接受协助并复制码发给你。」**  
   自己点断开：用「你已断开。若要再连，粘贴码后点「连接」。」，**不要**出本条中途掉线重连引导。  
   尚未连上失败：仍用 R003 `FriendConnectGuide`，本条不动。

3. **断在常用操作进行中**  
   最终主状态与引导须落到上面两句；**不得**长时间停留在「调用失败：Connection closed…」或英文协议原文。允许短闪后被 ConnectionLost 收口，验收以稳定后的界面为准。

4. **重连行为（不改协议）**  
   - **产品拍板**：未刷新会话码则旧码仍可再连；断开不作废当前码。  
   - **产品拍板**：未刷新会话码则旧码仍可再连；断开不作废当前码。  
   - 粘贴区里若还留着码和密码，「连接」应可再次发起配对（与今日一致）。  
   - 对方已「结束这次协助」并 `Stop` 后：再连应落到 R003「对方还没打开「接受协助」…」等已有句，不另发明。  
   - **不做**自动重连、后台静默重试、完整会话恢复。

5. **范围**  
   Windows 去协助端与 Avalonia 去协助端都改到；文案进 `HelperSessionCopy`（或并列常量类），两端共用。  
   接受协助端 R031「对方已连上 / 断开后回等待句」本条不改。  
   不改官网包、不改中继、不改 AI-SSH-Pro。

## 验收

1. 已连上后模拟/制造底层断开（非自己点断开）：主状态为「连接已断开。」，同屏可见重连引导句；五键按未连接规则收起；「连接」恢复可点。
2. **不得**在该情景主状态显示「对方已结束这次协助。」。
3. 协助方自己点断开：主状态为「你已断开。若要再连，粘贴码后点「连接」。」，无本条中途掉线重连引导句。
4. 尚未连上失败：仍为「连接失败」+ R003 原因句，无本条「连接已断开。」。
5. 断在「提议一项改动」或只读工具进行中：稳定后界面符合 1，无英文 `Connection closed` 主状态。
6. 对方仍在接受协助时，用原码再点「连接」可再次连上（或按 R003 给出明确失败原因）；对方已结束协助后再连，落到 R003 已有引导。
7. Windows 与 Avalonia 行为与文案一致；截图 `docs/screenshots/r043-*`（实现轮命名以产品 round 为准）。

## 不做

- macOS 正式下载、HTTPS、完整远程桌面 / 键鼠注入  
- 新增中继 JSONL 字段或「结束原因」协议  
- 自动重连 / 会话无感恢复  
- 改 EndAssistCopy、R031 被控主状态、R003 未连上句、trust-levels、InstallInstructions / Skill  
- 不在本文件另开包装轮；实现见 `docs/round-043.md`（R043 不包装）

- **修订**：取消「网络中途断开也可以用对方结束句、不必区分」中的文案策略；改为统一「连接已断开。」+ 重连引导，避免亲友误判。
