# 短凭证信任模型：S0 / S1 / S2

> 架构约定（2026-11-06）。本文是目标方案与威胁模型，不表示功能已实现。与 `tls-trust.md`、`quality-connection-credential.md`、`pake-unique-credential-eval.md` 交叉。

## 1. 目标与不变量

亲友主路径只复制两行「会话码：……」「验证密码：……」（新会话密码 8 位）；默认中继内置，仅高级设置可改。不要求复制地址或 remoteassist:pair 长串。**这是目标体验，不是现有短路径已安全可连的声明。**

业务通道仍是协助端到被控 Agent 的端到端 TLS；钉扎对象是 Agent 临时业务证书的 fp，不是中继证书。中继只转发，不终结业务 TLS。中继传输层 TLS 验证与业务证书钉扎是两层独立检查。

短码本身不能认证业务身份。「短码 + 密码」须通过 S1 密封指纹，或通过 S0 完整 PairQrPayload，取得有效 Agent fp 才能钉扎；后续 S2 由端到端 PAKE 认证该绑定。任何路径都不得在无 fp 时开放业务连接。

身份认证和本机三档写确认正交：通过身份验证不等于允许写入、自动放行或抬高权限；本轮不修改本机确认策略，也不修改 AI-SSH-Pro。

## 2. 威胁模型对比

| 属性 | S0 完整长载荷 | S1 密封 fp（过渡推荐） | S2 端到端 PAKE（强化评估） |
| --- | --- | --- | --- |
| 用户分享 | 含 fp 的完整 PairQrPayload | code + 8 位密码 | code + 8 位密码 |
| fp 根信任 | 用户可信 OOB 分享的载荷 | 默认官方中继诚实，不恶意替换绑定 | 两端密码认证的会话密钥与完整 transcript |
| 中继能否知道 pwd | 旧 guest_* 若传明文则能；不改变 OOB fp 独立性 | 现有 guest_join 若交明文，则能 | 不应能；guest_host/join 不提交明文或可逆密码载荷 |
| 已知 pwd 的恶意中继替换自身 fp | 原 OOB fp 钉扎应拒绝；不含其他授权旁路保证 | **能**重封自己的 fp，不能抵抗 | 两端未泄密、绑定和限速正确时应拒绝；仍可在线猜测/拒绝服务 |
| 业务 TLS 终点 | Agent | 运营方诚实时是 Agent；运营方作恶不保证 | PAKE 认证并绑定的 Agent |
| 是否兑现「服务器不知密码、唯一凭证」 | 否 | **否** | 有条件可兑现，须解决账号免密授权冲突并通过恶意中继测试 |

S1 与 S0 的独立身份引入强度**不等价**。S1 不是零信任中继方案。AEAD 只证明掌握派生密钥的一方生成密文；已获 pwd 的中继同样掌握密钥，能生成任意合法 sealed_fp。

S1 对外部被动窃听及通常网络篡改的保护依赖正确验证的中继传输 TLS、AEAD 校验及业务钉扎。不能声称抵抗被用户在高级设置中指定的**恶意**中继：它拿到 pwd 后可替换密封绑定。错误地址不可达/证书无效时应失败；一个可通过传输 TLS 验证但恶意的运营方仍属于 S1 信任边界之外。

另外，sealed_fp 暴露给攻击者时，其 AEAD 标签可用于离线验猜密码；code 是公开路由信息，不能计入秘密熵。8 位密码密封不具备 PAKE 的被动抗离线猜测性质。不得单独以“只存密文”宣称运营方无法知道 fp/pwd。

## 3. S1：短凭证 + 密封指纹（推荐的诚实中继过渡路径）

1. Agent 创建临时业务证书并获取 fp；guest_host 成功获得 code 后，由 Agent 在该 host 已绑定连接内登记 sealed_fp。登记只允许该会话 host，不能凭 code 任意覆盖。登记完成前不将会话标为短路径 ready。
2. 使用从 code || pwd 派生的密钥 AEAD 密封 fp。实现必须采用成熟 KDF/AEAD 库，不自造密码学；code/pwd 必须使用无歧义长度编码和版本化规范化规则，而非裸字符串拼接。密码 KDF 参数须有安全下限及资源上限，不接受中继任意降参。
3. 概念字段包括 format_version、suite、kdf_salt、受约束 KDF 参数、nonce、ciphertext、tag、会话实例标识及有效期。AAD 至少绑定产品/协议域、版本、code、实例、有效期；解封后验证 fp 格式、实例和本地有效期。具体线格式需实现轮评审，不把本草案当已部署协议。
4. guest_join 成功后返回 sealed_fp 及版本；协助端本地用密码解封，得到 Agent fp。只有传输验证、AEAD、上下文和有效期检查全部成功，才向业务 TLS 配置此 fp 钉扎。证书不匹配必须拒绝。
5. 封装与 join 扩展写入 [relay-protocol](relay-protocol.md) 的版本协商、字段、状态及错误码；S1 不应被当作仅文案改动。旧会话、旧中继不具备字段时安全失败。
6. sealed_fp 仅存 guest_sessions 等待态或等价旁路会话字段，默认随会话清理；不复制到长期审计。业务身份明文 fp、pwd、完整 PairQrPayload 禁止进入审计/管理台/普通日志。运行态是否现存 pwd/hash 须实现轮单独核实，不能因“审计不存”宣称“中继从未见过”。

UI 主按钮「复制会话码和密码」只复制两行，无地址/长串。高级入口「复制完整连接凭证」保留 S0。密码必须确实是新规则生成的 8 位，不可给旧 4 位密码简单补零伪装升级。

## 4. S0：完整载荷保留

完整 remoteassist:pair / PairQrPayload 含 Agent fp，由用户经可信渠道分享。适用于高级、排障、需要不依赖中继身份引入的场景。载荷内密码亦是秘密，应防止日志/审计/管理台泄漏；OOB 渠道被替换则 S0 根信任同样失效。

S0 的 fp 独立性不等于整个系统没有服务器授权旁路。若仍有仅凭 owner 声明授权的路径，不能称唯一凭证，见 [PAKE 唯一凭证评估](pake-unique-credential-eval.md)。

## 5. S2：不信任中继的强化方案

采用成熟端到端 PAKE：协助↔Agent 在仅路由管道上认证 pwd，密钥确认后在该认证信道交换/确认 Agent fp，随后钉扎业务 TLS。仅把协助端→中继 guest_join 换成 OPAQUE，不足以证明 Agent 绑定不能被中继伪造；必须具体说明 PAKE 的终点、登记信任、密钥持有人以及 TLS 绑定。

详细候选、重放、限速、唯一凭证冲突及恶意中继测试见 [pake-unique-credential-eval.md](pake-unique-credential-eval.md)。S2 是后续协议安全工程，不在本轮实现。

## 6. 迁移与废弃条件

- 过渡双路径：协助端接受两行短凭证和 S0 长载荷。被控主按钮只复制两行，高级入口可复制完整载荷；在未实现 S1 前不得先宣称短凭证可连。
- 旧会话无 sealed_fp、未知版本、解封失败、fp 缺失或不匹配：短路径必须阻断。提示「当前会话缺少安全验证信息，请在被控端创建新会话，或使用完整连接凭证」。不得 TOFU、跳过验证或自动明文。
- 显式使用 S0 是用户选择的独立根信任路径，不是错误后的未验证降级；不得悄悄以中继裸 fp 替代 OOB fp。
- S2 若用于唯一凭证模式，该模式不能自动回落 S1/旧明文 guest_join。必须在本机策略和能力协商中防止中继剥离 S2 能力而诱导泄密；未知能力失败，不发送 pwd 探测。
- 是否隐藏主路径长串须待 S1 稳定、兼容矩阵/安全验收完成、S2 评估与高安全替代路径明确后由产品决定。**隐藏不等于删除解析器或取消 S0 高级信任选择**；无日期承诺。

## 7. 明确禁止

禁止未验证降级、TOFU、自动 plaintext、跳过 TLS、主路径 --insecure；禁止用中继 TLS/服务器证书 fp 冒充 Agent 临时业务 fp；禁止将中继返回的裸 fp 或未可信绑定 fp 视为与 OOB 载荷同等强度；禁止把 pwd、明文 fp、完整载荷记入审计或管理台；禁止把 S1 宣传成服务器不知道密码。

## 8. 改动边界与开放问题

客户端：两行复制、短凭证解析、解封和 Agent TLS 钉扎、内置默认中继及高级改址、S0/S1 双路径解析；不改 AI-SSH-Pro。中继：guest_sessions 等待态封装字段、host 登记及 join 返回、版本/状态/错误语义；不终结业务 TLS。架构本轮只 docs。

开放：密码字符集/熵；KDF 参数在 Net48/.NET8/Linux 的性能；会话 TTL/一次性消费/竞争 join；封装最大长度和降参防护；字段扩展与现有 relay-protocol 的对照；高级改址风险说明；S2 库审计/FFI；账号免密与唯一凭证的产品取舍。上述均不得被误写为已实装。


## 9. 不可降级安全底线（与 S1/S0/S2 正交）

总原则：**安装鹊桥 ≠ 服务器可随时控制本机。**

### A / B 正交（禁止混写）

- **A（服务器不可自行取得控制）**：中继或其 DB/管理权限失陷时，伪造 paired、替换指纹/sealed_fp、伪造同账号或 owner 声明，均**不能单独**获得对被控机的读/写控制权；不能仅靠服务端声称「同账号」跳过本机配对/会话授权。
- **B（本机三档写确认）**：已获本机会话授权的协助者，可按本机选定的宽松 / 本次完全信任减少或免除逐次写确认。出厂默认仍是逐次写确认，这是**既有默认**，不是短凭证方案强制的安全验收项。本轮**不重置**既定三档（见 `trust-levels.md`）。

不得从 A 推导出「因此必须每次写确认」。身份认证成功只是授权判断的前置，不自动抬档。

### 六条底线

1. **中继失陷不能扩大授权**：见 A。S1 在「已知 pwd 的恶意中继」下可重封 fp，失败模式是协助端可能钉到错误对端；即便如此，也**不能**因此在未被控本机授予会话授权的情况下控制被控机。
2. **短码身份须端点验证并与会话绑定**：不能只写「有 TLS」。S1 现状/过渡：guest_join 若仍交明文 pwd，中继可知密码（须如实写）；抗冒充依赖 sealed_fp 解封 + 业务 TLS 钉扎 + 本机会话授权。PAKE 唯一凭证目标下：密码不得明文/可逆回传中继，端点 PAKE 验证（见 `pake-unique-credential-eval.md`）。
3. **本机授权只能本机授予**：读权限也需身份验证 + 本机会话授权（配对确认或等价授权）。写操作频率遵循本机信任档位（B），不是服务器策略。
4. **安装/启动首页 ≠ 开启远程协助**：自动上线、自有设备免密须单独本机授权，并提供可撤销入口。
5. **码可用性 vs 会话授权（拆开）**：
   - **码可用性**：会话码是否仍可被中继接受 join（「结束只断开不废码」若仍成立，仅指码可能仍可再次尝试连接）。
   - **会话授权**：本次已授予协助者的读/写/信任档位。结束协助必须撤销本次授权与本次完全信任，并拒绝旧请求重放。
   - 即便旧码仍可用，也**不得**静默续用已撤销的本次授权；再次连接须重新完成本机会话授权。
6. **安全验收**：须用受控恶意中继 / 伪造账号声明 / 重放请求验证。编译或文档 PASS ≠ 安全 PASS。

### S1 与中继失陷

即便 S1 采用「默认官方中继诚实」作为**指纹引入**假设，上述底线仍然成立：诚实假设**不得**削弱本机授权。S1 **不**等于「服务器不知密码」。
