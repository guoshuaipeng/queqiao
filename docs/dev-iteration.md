# 鹊桥 · 规范化开发迭代步骤

> **站立方**：鹊桥-架构 与 鹊桥-产品 共同定稿并落实。  
> **决策载体**：本文 + `docs/PRODUCT.md` / `docs/roadmap.md` / `docs/PRODUCT-VERSIONS.md` / `docs/agents/`。  
> **授权边界**：写文件 ≠ 上机授权 ≠ push 授权；生产中继/公网上机须用户另授。  
> **本文效力**：本规范本身**不视为** R049 / R050（或任何具体条目）的实现授权；交互须用户确认、安全/凭证 blocked 须评估收口后再授权、生产改动须另授——这些门槛一律保留。

## 一轮标准步骤

### 1. 选题

产品**自行出需求**（可全新提出，不限于既有条目）。提出后须登记进 `docs/PRODUCT-VERSIONS.md` 和/或 `docs/roadmap.md`（含状态、验收、约束）。

**禁止凭空堆功能。** 出需求时产品须：

- **核实现状 / 查重**：对照已有版本条、roadmap、round、quality / scene，避免重复或与现行决策冲突。
- **写清**：用户价值、范围与**非目标**、优先级、验收标准、依赖（含协议 / 体验确认 / 环境）。
- 队列空时：继续发现与重评（复盘、质量债、用户反馈），而不是硬凑条目。

状态纪律：

- `草稿` / `暂停` / `blocked`：**不推进实现**。
- 新需求：先标状态，再进入实现队列。

### 2. 规格

| 涉及 | 谁做 | 要求 |
|------|------|------|
| 交互 / UI | 鹊桥-体验 | 出草案并标「待用户确认」；**确认前不交 UI 实现** |
| 协议 / 信任 / 凭证 | 鹊桥-架构 | 先写/改 `docs/`（如 `architecture.md`、`relay-protocol.md`、`tls-trust.md`、短凭证 / PAKE 评估等）；架构**不写**业务功能代码、不上机 |

### 3. 授权

鹊桥-产品明确「**本轮实现授权**」。

- **拍板 ≠ 授权实现**。
- `blocked` 项（如 R050 严格唯一凭证）：须架构评估收口 + 产品对照验收标准后，再授权动码。

### 4. 实现

- **鹊桥-客户端**：`src-net48` / `src` / `installer` 等（按本仓实际边界）。
- **鹊桥-服务端**：`relay` / `site`。
- 协议变更：**先更新** `docs/relay-protocol.md`，再改 Go；客户端跟随文档。
- **不改 AI-SSH-Pro**；本机开发；生产中继 / 公网上机须另授。

### 5. 自测

实现侧跑约定测试矩阵。

**编译 / 文档 PASS ≠ 运行 PASS ≠ 公网验收。**

### 6. 专项测试

测试角色（协助端 / 被控端 / 管理端等）在**约定环境**验证；结果写各自渠道。

**当前约定（可随派工更新）：**

- 协助 / 被控：可测 **Linux 客户端**路径（结果须标明 Linux；**勿冒充** Net48 Windows 亲友主路径 PASS）。
- 管理端：可在 bot 电脑浏览器测 site / 管理后台。
- Windows 亲友主路径仍以 **net48** 为准；另授权 Windows 测试环境后再测。
- **测试环境须遵守用户限制**（例如：勿在用户日常本机凑合测、勿经消息转发会话密码等）；以当时用户约束与架构派工为准。

### 7. 验收

产品对照验收标准收口；需用户确认的标「待验收」→ 用户确认后标「完成」。

**要真实证据，禁止虚报：**

- 构建 / 编译通过 ≠ UI / 运行通过。
- Linux 客户端路径通过 ≠ Net48 Windows 亲友主路径通过（须分标）。
- 专项测试须在约定且符合用户限制的环境完成；缺环境记阻塞，不写假 PASS。

### 8. 收尾

- 更新 `docs/round-NNN.md`、`docs/iteration-status.md`、`docs/retro.md`。
- 可推广的短规则写入 `docs/dev-rules.md`（保持精简，勿堆长文）。

## 硬规则

1. 决策落仓库 `docs/`，**不靠** bot 聊天记忆。
2. 角色边界见 `docs/agents/`。
3. Windows 亲友主路径 = **net48**；Avalonia / Linux = Mac / Linux 路径，勿混称 PASS。
4. 严格唯一凭证 / R050：产品决策可锁定，但实现保持 **blocked**，直至评估收口并获实现授权。
5. 测试 bot 少打扰用户；架构派工与环境约束以本文与当时派工为准。
6. 本规范文档的写入/更新**不等于**对 R049、R050 或其它条目的实现授权。

## 协作

| 角色 | 在本流程中 |
|------|------------|
| 鹊桥-产品 | 出需求（含查重与价值说明）、登记、授权实现轮、验收收口（凭真实证据） |
| 鹊桥-架构 | 协议 / 信任规格、迭代流程文档（本文唯一写入者）、不写业务码 |
| 鹊桥-体验 / 场景 | 交互与场景规格（体验须用户确认） |
| 鹊桥-客户端 / 服务端 | 授权后实现与自测 |
| 鹊桥-迭代 | 按 PRODUCT-VERSIONS「待开发」与本文推进小步迭代 |
| 测试-*（协助 / 被控 / 管理等） | 约定环境专项验证 |
