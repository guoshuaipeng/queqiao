## 0. 哪些已由用户直接确认，哪些仍是待确认草案

### 0.1 用户已直接确认（本稿遵守，不当作待选项）

| 项 | 口径 |
|----|------|
| 唯一连接凭证 | 严格只认 **code + 密码**；自己的设备也要输入，不另设账号免密、不另设设备密钥快捷授权 |
| 服务器边界 | 安装/上线 ≠ 可被服务器随时控制；服务器不能自行取得或扩大对本机的控制权 |
| 短凭证目标 | 对外复制/粘贴目标为 **`会话码-8位密码`**；中继用默认地址，地址仅在「高级」里改 |
| 写确认与身份认证正交 | 三档（每次询问 / 宽松 / 本次完全信任）独立于「怎么连上」；宽松或本次完全信任时不要求逐次弹窗 |
| 短码安全前提 | 短凭证不能靠删校验达成；需成熟 **PAKE（或同等）** 方案评估与验证后，密码可不回传中继且中继不能冒充协助者。未验证前不宣称已满足 |

### 0.2 产品传来、**尚未**经用户确认的草案（不得写成「用户已批准」）

| 项 | 说明 |
|----|------|
| **多码：临时协助码 vs 长久自控码** | 产品希望同一台被控机可有两类独立 code+密码；创建/展示/复制/撤销交互见 §3。**本节整段均为待用户确认的产品草案。** |
| 长期码「无人值守」预授权 | 产品补充口径见 §3.2：长期码仍每次端点验证 code+密码；本机显式允许该码无人值守后，**连接成功可不再等现场点「允许协助」**；这与写确认策略分开，**不等于免验证、不等于自动完全信任写操作**。仍待用户确认是否采纳。 |

### 0.3 本稿范围

1. **单主窗口**：首页 / 去协助 / 接受协助在同一窗口内页切换。  
2. **默认中继 + 高级改地址**。  
3. **多码 UI 草案**（临时 vs 长久），含点击路径、原文、状态、验收口径。  

**不做**：业务实现、开轮授权、改中继协议、发明 TTL/数量上限为既定决策、宣称 PAKE/短码安全已落地。

## 1. 单主窗口（页内切换）

### 1.1 目标

一个主窗口承载：

- **首页**：两张入口卡「接受协助」「去协助别人」+「高级」  
- **接受协助页**（被控）  
- **去协助页**（协助方）  

顶栏随页变；「返回首页」回到首页卡，**不新开第二主窗口**。

### 1.2 点击路径

```
启动 App
 └─ 首页（同窗）
     ├─ 点「接受协助」→ 同窗切到「接受协助」页；顶栏「返回首页」
     ├─ 点「去协助别人」→ 同窗切到「去协助」页；顶栏「返回首页」
     └─ 点「高级」→ 同窗打开高级面板/页（中继地址、写操作信任等级等）；可返回
```

### 1.3 状态与安全边界（推荐定稿，待用户确认）

- 安全确认对话框仍可覆盖主窗口，单主窗口不取消配对、写操作、完全信任等本机确认。
- 返回首页只切页、不结束会话；首页持续显示「正在接受协助」或「正在协助对方」及「返回会话」「结束这次协助」，不能像已结束。
- 有活动会话时切换另一角色，确认：「切换模式会结束当前协助，是否继续？」按钮「结束并切换 / 取消」。单窗口阶段不同时开启两个角色。
- 关闭主窗口按退出程序处理，不静默藏后台。确认：「退出会断开所有连接，并停止接受新的协助，直到再次启动。长久码不会被撤销。」按钮「退出程序 / 取消」。无人值守开启时也须显示此影响。最小化与退出区别明确。
- 没有活动连接但已开启无人值守，退出同样提示会停止接受协助。首页不会自动开启接受协助；已显式启用无人值守的状态必须全局可见。

### 1.4 去协助页相对现状的改动点（设计）

对照 `r021-*`：现状有「账号免密」「连接这台电脑」。按用户已确认的唯一凭证：

- **去掉**「账号 (可选) / 免密连接 / 设备列表连接这台电脑」主路径入口（可整体不展示；若暂时保留壳，须禁用并注明「已取消免密，请粘贴 code+密码」——**推荐直接去掉，避免误导**）。  
- 主路径只留：粘贴 `会话码-8位密码` →「连接」。  
- MCP 安装说明可收入「高级」或页底轻量区，不与「连接」抢主按钮。  
- 顶栏副文案改为：`粘贴对方发来的连接凭证（会话码和密码），点连接。`（去掉「或登录账号免密…」）

### 1.5 可验收（设计验收口径；未实现前不算通过）

1. 首页 → 接受协助 → 返回首页 → 去协助，始终同一进程主窗口，无第二主窗。  
2. 有活动会话时返回首页保留可见会话条；切换角色需结束确认；退出明确断开全部并停止无人值守接入，不静默隐藏。  
3. 写确认/配对/完全信任仍为模态；单窗口改造不合并掉这些对话框。  
4. 去协助主路径无免密/账号连设备入口。

## 2. 默认中继；地址仅高级设置修改

### 2.1 行为

- 安装后**自动使用产品默认中继**；首页与发码/连接主路径**不展示**主机、端口、TLS 等。  
- 改地址：**高级 → 中继服务器**（或同等分组）。  
  - 展示：当前地址（完整显示）。  
  - 操作：编辑 → **显式「保存」** 才生效；「恢复默认」。  
  - **不**在保存时自动迁移活动会话到新地址；**不**自动把新地址写进已复制的凭证或自动重发凭证。  
  - 有活动会话时点保存：先提示 `保存后，当前这次协助仍走原来的服务器，不会自动转到新地址。要改用新地址，请先结束这次协助，再重新连接。` 按钮：`仍保存` / `取消`。

### 2.2 原文建议

- 分组标题：`中继服务器`  
- 说明：`一般不用改。只有对方或管理员告诉你换服务器时才改这里。`  
- 保存成功：`已保存。新的连接会使用新地址。`  
- 未保存离开：`地址还没保存，确定离开吗？` → `继续编辑` / `丢弃更改`

### 2.3 可验收（设计）

1. 主路径发码/连接不出现可改的中继地址。  
2. 仅高级可改；须显式保存；恢复默认可用。地址并非秘密，不作无意义掩码。  
3. 保存不踢迁活动会话、不自动外发凭证；有会话时有上述说明。

## 3. 多码草案（产品待用户确认）：临时协助码 vs 长久自控码

> **整节为产品草案，用户尚未确认。** 若用户否决多码，则 §1–§2 与唯一凭证仍成立，接受协助页退回「单一临时码」模型。

### 3.1 共同原则（与已确认安全口径对齐）

- 每条码 = **独立的一对** `会话码` + `8 位密码`；复制形态目标为 **`会话码-8位密码`**（短凭证）。  
- **任何码都不是免密**：每次连接都须在端点完成 **code + 密码** 验证（目标为 PAKE 等；架构未验证前不宣称已做到）。  
- 创建码 **不** 自动打开「完全信任」；**不** 自动「开机即接受协助」。  
- 密码默认遮挡（`••••••••`），旁有「显示」；**普通日志不得写明文密码或完整凭证**。  
- 复制成功须剪贴板真实写入后再提示；失败用人话，可手选复制。  
- 输入正确凭证 **不能** 绕过本机为该码配置的**操作范围**（只读/可提议改动等）与**写确认策略**。

### 3.2 长期码：配对预授权 ≠ 免验证 ≠ 免写确认（产品补充口径，待确认）

避免误读成「长期码不需要验证」：

| 层级 | 长期码（草案） | 说明 |
|------|----------------|------|
| A. 身份验证 | **每次连接**仍验证 code+密码 | 绝不是免密；服务器不知密码时也不能冒充 |
| B. 配对/「允许协助」弹窗 | 仅当本机**已对该长期码显式勾选「允许无人值守连接」**时，验证成功后**不再等现场点「允许协助」** | 否则无法无人值守；未勾选则与临时码一样要现场允许 |
| C. 写操作确认 | **仍跟三档信任等级**；预授权配对 **不** 自动变成完全信任 | 宽松/每次询问照常；普通完全信任仍仅本次会话；长期码跨会话预授权是下节独立待确认例外，不自动继承 |
| D. 操作范围 | 本机授予该码的范围（如仅查看 / 可提议改动） | 凭证正确也不能越权 |

界面须把 B 与 C 分开两句，禁止合成一句「不用再确认」导致用户以为写操作也不问了。

**无人值守开关（草案原文）：**

- 勾选项：`允许用这条码无人值守连接（仍要密码；连接成功后不再弹「允许协助」）`  
- 旁注：`不会因此跳过改动确认。对方要改这台电脑时，仍按你在「对方要改这台电脑时」里的选择询问。`  
- 默认：**不勾选**。须本机显式勾选并（建议）二次确认：  
  - 标题：`允许这条码无人值守连接吗？`  
  - 正文：`之后用这条码连上时，不必人在电脑前点「允许协助」，但仍须正确密码。这不是免密，也不会自动允许对方改动。`  
  - 按钮：`确定允许` / `取消`

### 3.2.1 无人在场也能改动：独立持久预授权（待用户确认）

旧「完全信任」只对当前会话有效，不能直接跨会话保存。建议普通临时协助维持旧定义；仅对某条长久码提供独立配置：

- 开关「允许无人值守连接」，默认关闭。打开只免现场配对确认，不免身份验证。
- 操作范围选「只查看」或「允许改动」，默认只查看。
- 允许改动后选询问策略：「每次询问」「宽松」，默认每次询问。无人时需本机确认的操作等待或超时拒绝，绝不自动允许。
- 另设未勾选的选项「允许这条长久码改动时不再询问」。本机二次确认标题「允许这条长久码持续免确认改动吗？」正文「以后任何拿到这条码和密码的人，都能在你不在电脑前时，按你授予的范围改动这台电脑，不再弹窗询问。这项授权跨会话保留，直到你关闭或撤销这条码。操作仍会记录。」按钮「允许持续免确认 / 取消」。这是新增持久例外，须用户确认，不是既有本次完全信任。
- 主界面常驻「无人值守已开启」；有持久免确认时加「有长久码允许改动不再询问」。入口「管理长久码」「关闭全部无人值守」。
- 关闭某码无人值守或撤销该码：立即断开该码全部连接、取消尚未开始的操作及待确认请求，阻止复用旧会话权限。已执行的改动不会自动回滚；已启动的系统进程不能承诺都能撤回。
- 关闭持续免确认时同样先断开该码活动会话，后续按新策略连接，不让旧授权继续存活。其他码不受影响。
- 撤销在被控端生效；本稿不承诺人在异地能仅靠服务器撤销本机授权。异地管理如需另做，也必须端点认证，不增服务器后门。
- 开机自动接受协助为另一个默认关闭的选项，须用户单独选择且架构确认支持，不和创建长久码捆绑。

### 3.3 两类码怎么区分（展示）

| | 临时协助码 | 长久自控码 |
|--|------------|------------|
| 用途文案 | `给亲友或客服用的一次性协助` | `给你自己常用的长久连接（仍要密码）` |
| 默认持久 | 临时码生命周期待确认：建议「结束临时协助」同时作废该临时码，下次显式开启生成新码；这与旧「结束只断开不废码」不同，需产品及用户确认，不默改 | **须本机显式「创建长久码」** 才存在；带风险说明 |
| 列表展示 | 当前临时码卡片（主路径默认） | 「我的长久码」列表，可多条（数量上限**不**在本稿定为产品数字） |
| 主按钮 | `复制连接凭证` | 每条：`复制连接凭证` |

**密码展示：** 默认 `验证密码：••••••••`；点「显示」才见 8 位。复制时复制完整 `码-密码`，不依赖屏幕上是否显示。

### 3.4 接受协助页 · 点击路径（草案）

```
接受协助页
 ├─ 【当前临时协助】卡片
 │    ├─ 会话码（可显示） / 验证密码（默认遮挡）
 │    ├─ 主按钮「复制连接凭证」
 │    ├─ 「更多」→「作废并换新的临时码」（先确认）
 │    └─ 状态：等待连接 / 已有人连接 / 对方已离开…（人话，忌 PAIR_OK）
 ├─ 【我的长久码】（待确认模块）
 │    ├─ 空态：`还没有长久码。长久码方便你自己反复连，但任何人拿到码和密码都能按你的授权连上。`
 │    ├─ 按钮「创建长久码」→ 风险说明 → 确认创建 → 生成一对新码（不自动无人值守、不自动完全信任）
 │    └─ 每条：名称（可改）、码、密码遮挡、复制、开关「允许无人值守…」、撤销
 └─ 底栏/主区：「结束这次协助」与信任等级非默认提示（沿用 trust-levels，操作名以产品已收口为准）
```

**创建长久码 · 风险说明（创建前必读，确认后才生成）：**

- 标题：`创建长久码？`  
- 正文：`长久码和密码谁拿到都可以按你的设置连接这台电脑。请只存在你信任的设备上，不要发到公开群。创建后不会自动允许改动，也不会开机自动接受协助。`  
- 按钮：`创建` / `取消`

**复制成功（两类共用，与短凭证目标一致）：**  
`连接凭证已复制，请完整发给对方。`  
（若剪贴板为 `码-密码` 短串，界面说明用「连接凭证」，不出现指纹/TLS。）

**协助端粘贴：**  
- 标签：`粘贴连接凭证`  
- 旁注：`格式为「会话码-密码」，一次粘贴即可。`  
- （R044「完整连接凭证/缺安全验证信息」文案：在短凭证+PAKE 方案拍板前，产品须统一亲友可见句；本稿推荐最终亲友句对齐短串，缺段时：`连接凭证不完整，暂时无法连接。请让对方重新复制后再发。` **不**引导用户去理解指纹。）

### 3.5 撤销与结束：必须讲清（推荐明确，不模糊）

| 动作 | 含义 | 推荐行为 | 确认原文（推荐） |
|------|------|----------|------------------|
| **结束临时协助** | 只结束临时通道，不改长久码 | 建议断开该临时码连接并作废临时码；不影响长久码的会话或无人值守 | 「结束临时协助后，这条临时码不能再连。长久码不受影响。」按钮「结束临时协助 / 取消」 |
| **作废并换新的临时码** | 旧临时码失效 | **推荐：同时断开**所有正用该临时码的活动会话 | 标题：`作废现在的临时码？` 正文：`旧码将不能再连。若现在有人连着，也会断开。` 按钮：`作废并断开` / `取消` |
| **撤销某条长久码** | 该长久码永久失效 | **推荐：同时断开**所有正用该长久码的活动会话；列表移除或标「已撤销」 | 标题：`撤销这条长久码？` 正文：`撤销后，这条码和密码立刻失效。若现在有人正用它连着，也会断开。其他长久码和当前临时码不受影响。` 按钮：`撤销并断开` / `取消` |

**禁止**：按钮只写「删除」却不说明是否踢当前会话；禁止撤销后旧连接仍可写操作。

### 3.6 限速 / 认证 / TTL / 数量

- 猜密码限速、PAKE、中继是否可见密码等：**待架构评估**，本稿不发明协议。  
- **不**把「有效期天数」「最多几条长久码」写成已定产品决策；若实现需要上限，由产品另开确认。  
- UI 可预留「创建失败：请稍后再试」类人话，不暴露服务器细节。

### 3.7 多码可验收（仅当用户确认采纳多码后；现为设计口径）

1. 临时码与长久码为不同 code+密码对；复制均为一次 `码-密码`（目标形态）。  
2. 创建长久码必经风险说明；默认无无人值守、无完全信任、无开机自启接受协助。  
3. 无人值守勾选文案同时说清「仍要密码」与「改动仍按信任等级」；未勾选时长期码连上仍要现场「允许协助」。  
4. 撤销长久码 / 作废临时码的确认文案含「是否断开当前会话」；推荐实现为断开。  
5. 「结束这次协助」≠「撤销长久码」。  
6. 密码默认遮挡；日志无明文密码；复制成功句仅在真实复制成功后出现。  
7. 去协助侧无免密旁路；自有设备也粘贴 code+密码。

## 4. 与旧质感文案的关系

- 连上后忌 `PAIR_OK`、断开后人话下一步：续篇结论可沿用，单窗口下同样适用。  
- 信任等级入口仍在本机「高级 → 对方要改这台电脑时」；与码类型、无人值守预授权分开。  
- R044「完整载荷」亲友文案：与用户要的短 `码-密码` 冲突时，**以用户已确认短凭证目标为准做亲友表达**；安全能力等架构，不在 UI 上假装已可删校验。

## 5. 明确非目标 / 不宣称

- 不宣称 PAKE、短码防中继冒充、限速已实现或已验收。

## 6. 请产品在用户所在会话展示并确认

**方案摘要：**

主窗口内切换首页、接受协助、去协助；返回首页保留醒目的会话条，切换角色先确认结束当前协助，退出程序会停止全部接入。服务器默认，高级显式保存地址。连接始终只用 code+8位密码，自己的电脑也输入。

接受协助页分「临时协助码」与「长久自控码」。长久码在本机创建，可命名、复制、撤销；每次仍验证密码。本机提前开启无人值守后，连接免现场点允许；默认只查看、默认不允许免询问改动。若另在本机明确开启「持续免确认改动」，则只对该长久码跨会话保留，主界面醒目标示，随时可关闭并断开该码连接。普通临时协助的完全信任仍仅本次有效。结束临时协助不影响长久码。开机自动接受另设默认关闭选项。

**请用户确认的问题：**「按这套方案做吗？尤其是长久码可单独开启跨会话的免确认改动；临时协助结束时，建议同时作废临时码、但不影响长久码。」

若用户仅确认部分，应记录逐项范围，未确认的持久授权与临时码失效规则不能当作已批准。
